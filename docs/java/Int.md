# int — целое число со знаком

## Что это

Примитивный тип: 32 бита, 4 байта, со знаком. Проверено запуском:

```
Integer.MIN_VALUE = -2147483648
Integer.MAX_VALUE =  2147483647
Integer.SIZE      = 32 бит
Integer.BYTES     = 4
```

Всего значений `2^32`, чуть больше четырёх миллиардов. Отрицательных ровно `2^31`, неотрицательных тоже `2^31` — но в эту половину входит ноль, поэтому **положительных на одно меньше**, чем отрицательных. Асимметрия видна прямо в границах: `2147483647` против `-2147483648`.

## Как хранится в битах

Схема — **дополнительный код** (two's complement). Старший бит читается как знак: `0` у неотрицательных, `1` у отрицательных.

```
Integer.MAX_VALUE   2147483647   0111 1111 1111 1111 1111 1111 1111 1111   7FFFFFFF
0                            0   0000 0000 0000 0000 0000 0000 0000 0000   00000000
Integer.MIN_VALUE  -2147483648   1000 0000 0000 0000 0000 0000 0000 0000   80000000
```

`MAX_VALUE` — знаковый бит ноль, остальные 31 единицы: больше в положительную сторону не выжать. `MIN_VALUE` — знаковый бит единица, остальные нули. Ноль — все 32 нуля; «минус нуля» у целых нет, в отличие от `double`.

Ещё две показательные величины:

```
 1   0000 0000 0000 0000 0000 0000 0000 0001   00000001
-1   1111 1111 1111 1111 1111 1111 1111 1111   FFFFFFFF
```

Минус единица — все единицы. В этом и смысл дополнительного кода: `1 + (-1)` даёт все нули с уносом за пределы 32 бит, то есть ровно ноль. Отдельный алгоритм для вычитания не нужен, вычитание — это сложение с отрицательным.

## Диапазон замкнут в кольцо

Шаг за верхний край приводит на нижний, и наоборот:

```
Integer.MAX_VALUE + 1 = -2147483648
Integer.MIN_VALUE - 1 =  2147483647
```

В битах видно, почему:

```
  0111 1111 1111 1111 1111 1111 1111 1111
+                                       1
= 1000 0000 0000 0000 0000 0000 0000 0000
```

Единицы переполнились в знаковый бит, и число мгновенно стало самым отрицательным. Никакой проверки при этом не происходит — это обычное двоичное сложение, просто старший разряд по соглашению означает знак.

**Арифметика `int` в Java не сигнализирует о переполнении.** Ни исключения, ни предупреждения: результат просто оказывается неверным.

```
100000 * 100000 = 1410065408
```

Настоящий ответ — десять миллиардов, он в `int` не влезает.

## Три следствия, которые спрашивают на собеседовании

### Модуль отрицательного числа бывает отрицательным

```
Math.abs(Integer.MIN_VALUE) = -2147483648
-Integer.MIN_VALUE          = -2147483648
```

Не ошибка реализации. Значения `+2147483648` в `int` не существует: код `1000 0000 ... 0000` уже занят под `MIN_VALUE`, свободной комбинации не осталось. `Math.abs` по документации возвращает аргумент как есть, если результат не представим.

### Деление тоже умеет переполняться

```
Integer.MIN_VALUE / -1 = -2147483648
```

Единственный случай, когда деление `int` даёт переполнение, — по той же причине.

### Сравнение вычитанием ломается

Приём `return first - second` как компаратор верен, только пока разность влезает в `int`. Переполнение возможно, когда у операндов **разные знаки** и истинная разность достигает `2^31`:

```
2147483647 - (-1) = -2147483648
```

Число, которое должно было быть больше всех, оказалось меньше всех. Если оба значения неотрицательные или оба неположительные, разность гарантированно влезает — например, с полем «возраст» вычитание не сломается никогда. Но опасно полагаться на это: поле может начать принимать отрицательные значения.

Правильно — `Integer.compare(first, second)`.

Разбор с таблицей пар — класс `demo.IntSubtractionOverflow`, тема компараторов — [`ComparableAndComparator.md`](ComparableAndComparator.md).

## Как ловить переполнение

Методы `Math.*Exact` делают то же самое, но бросают исключение вместо тихой порчи результата:

```
Math.addExact(Integer.MAX_VALUE, 1)   -> ArithmeticException: integer overflow
Math.multiplyExact(100000, 100000)    -> ArithmeticException: integer overflow
```

Есть `addExact`, `subtractExact`, `multiplyExact`, `incrementExact`, `negateExact`, `toIntExact`.

Второй способ — считать в `long`, у которого запас на порядки больше:

```
(long) Integer.MAX_VALUE + 1 = 2147483648
Long.MAX_VALUE = 9223372036854775807
```

Приведение обязано стоять **до** операции. `(long) (Integer.MAX_VALUE + 1)` уже поздно: переполнение случится в `int`, и в `long` уедет испорченное значение.

В алгоритмических задачах это встречается в двух местах: середина отрезка в бинарном поиске (`(left + right) / 2` переполняется на больших индексах, безопасно `left + (right - left) / 2`) и накопление суммы массива.

## Остаток от деления бывает отрицательным

```
-7 % 3 = -1
Math.floorMod(-7, 3) = 2
```

Оператор `%` в Java берёт знак от делимого, а не от делителя. Для «математического» остатка, всегда неотрицательного при положительном делителе, есть `Math.floorMod`. Это важно, когда остаток используется как индекс массива: отрицательный индекс даст `ArrayIndexOutOfBoundsException`.

Причина расхождения в том, что оператор `/` **усекает** к нулю, а `Math.floorDiv` округляет вниз, и остаток подстраивается под своё деление. Разбор — [`Rounding.md`](Rounding.md).

## Типичные вопросы на собеседовании

**Какой диапазон у `int` и почему он несимметричный?**
От `-2147483648` до `2147483647`. Несимметричен потому, что ноль занимает место в неотрицательной половине, и положительных значений остаётся на одно меньше.

**Что такое дополнительный код и зачем он?**
Схема хранения знаковых целых, где отрицательное число — это дополнение до `2^32`. Позволяет складывать и вычитать положительные и отрицательные одинаковой схемой, без отдельного алгоритма и без «минус нуля».

**Что произойдёт при переполнении `int`?**
Ничего видимого: значение молча завернётся по кольцу. Если нужна диагностика — `Math.addExact` и родственные, они бросают `ArithmeticException`.

**Чему равен `Math.abs(Integer.MIN_VALUE)`?**
Самому `Integer.MIN_VALUE`. Положительного значения такой величины в типе не существует.

**Почему `(left + right) / 2` в бинарном поиске — плохо?**
Сумма двух больших индексов переполняет `int` и становится отрицательной, из-за чего середина уезжает влево от начала отрезка. Безопасная запись — `left + (right - left) / 2`.

**Чему равно `-7 % 3`?**
`-1`: оператор `%` берёт знак от делимого. Неотрицательный остаток даёт `Math.floorMod`, там будет `2`.
