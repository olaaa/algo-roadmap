# Переменные, значения и где они лежат

*Почему `++` работает на элементе массива*

Проверено на JDK 25 (JetBrains Runtime).

## Откуда вырос вопрос

При разборе [`ValidAnagram`](../problems/block02_strings_stack/ValidAnagram.md) встретилась строка:

```java
letterCounts[s.charAt(currentIndex) - 'a']++;
```

Неочевидно в ней то, что `++` применён не к простой переменной, а к элементу массива.

## Как отличить переменную от значения

`++` и составные присваивания применяются к любому выражению, **в которое можно присвоить**. Проверка: допиши к выражению `= 5;` и посмотри, компилируется ли.

```java
letterCounts[0] = 5;    // компилируется
count = 5;              // компилируется

s.charAt(0) = 5;        // не компилируется
map.get("a") = 5;       // не компилируется
```

Что скажет `javac`:

```
s.charAt(0) = 5;
        ^
  required: variable
  found:    value
```

«Требуется переменная, получено значение» — у результата метода значение есть, а переменной, в которую его записать, нет.

Признак без компилятора чисто синтаксический: **круглые скобки вызова в конце — присвоить нельзя, всё остальное (имя, точка-поле, квадратные скобки-индекс) — можно.**

## Где что лежит

![Кадр метода и куча](img/method-frame-and-heap.svg)

*Рис. 1. Кадр метода на стеке потока и объекты в куче*

**Кадр** (frame) кладётся на стек потока при вызове метода и снимается при выходе. Внутри две части: массив локальных переменных (**слоты**, нумерация с нуля) и **стек операндов** — рабочая площадка для промежуточных значений.

В слоте лежит либо сам примитив, либо **ссылка** на объект в куче. Объект в кадр не помещается.

**Куча** (heap) — общая на всю программу. Массив там обычный объект, а его элементы — такие же места хранения, как поля.

Отсюда ответ на исходный вопрос. `letterCounts[1]` — не вызов, возвращающий `int`, а способ назвать место хранения: пара «ссылка плюс индекс». Ровно эта пара и лежит на стеке операндов на схеме. Разница с локальной переменной только в адресации:

| Что | Как называется место |
|-----|----------------------|
| локальная переменная | номер слота |
| поле | ссылка на объект плюс имя поля |
| элемент массива | ссылка на массив плюс индекс |

У результата метода закреплённого места нет: копия ложится на стек операндов, живёт до следующей инструкции и никому не принадлежит.

## С коллекциями так нельзя

`map.get(key)++` не компилируется по той же причине. Для счётчиков в `HashMap`:

```java
map.merge(key, 1, Integer::sum);
```
