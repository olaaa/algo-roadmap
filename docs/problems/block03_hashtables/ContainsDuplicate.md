# 217. Contains Duplicate

*Наличие дубликатов (дословно: содержит дубликат)*

**Сложность:** Easy · **Паттерн:** множество виденного (seen set) · **Класс:** `block03_hashtables.ContainsDuplicate`

## Условие

Дан массив целых чисел `nums`. Вернуть `true`, если хотя бы одно значение встречается в массиве **больше одного раза**, и `false`, если все элементы различны.

Ни индексы, ни само повторяющееся значение возвращать не нужно — только факт.

## Примеры

### Пример 1

```
Вход:  nums = [1, 2, 3, 1]
Выход: true
```

Единица встречается на позициях 0 и 3.

### Пример 2

```
Вход:  nums = [1, 2, 3, 4]
Выход: false
```

Все элементы различны.

### Пример 3

```
Вход:  nums = [1, 1, 1, 3, 3, 4, 3, 2, 4, 2]
Выход: true
```

Дубликат находится уже на второй позиции, и дальше массив можно не смотреть.

### Пример 4

```
Вход:  nums = [7]
Выход: false
```

Один элемент — повторяться нечему.

## Ограничения

- `1 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`

## Почему такие ограничения

Диапазон значений `±10^9` — это то, что отличает задачу от подсчёта по алфавиту в блоке 2. Массив-счётчик здесь завести нельзя: под все возможные значения понадобилось бы два миллиарда ячеек. Поэтому вместо массива нужна хеш-таблица, а точнее `HashSet` — множество уже виденных значений.

Длина до `10^5` отсекает перебор парами за `O(n²)`: это порядка `10^10` сравнений.

## Идея решения

Идём по массиву и складываем значения в `HashSet`. Перед добавлением спрашиваем множество, не встречалось ли значение раньше. Встретилось — ответ `true`, дальше идти незачем.

Возвращать `true` надо **сразу**, а не дочитывать массив: как только дубликат найден, ответ уже не изменится.

```java
Set<Integer> seenValues = new HashSet<>();
for (int currentValue : nums) {
    if (!seenValues.add(currentValue)) {
        return true;
    }
}
return false;
```

Здесь использовано свойство `add`: он возвращает `false`, если элемент уже был в множестве. Это позволяет обойтись одним обращением к таблице вместо пары `contains` + `add`.

Про сам приём — [`Pattern_HashMap.md`](Pattern_HashMap.md), форма «множество виденного».

### Куда ставить `return`

Утверждение — «**существует** пара одинаковых элементов». Значит находка возвращается изнутри цикла, а `false` — после цикла, когда весь массив просмотрен и повторов не нашлось. Это приём 3 из [`heuristics.md`](../../heuristics.md).

Тут же кроется частая ошибка: писать `return false` внутри цикла, в ветке «этого значения ещё не было». Одно уникальное значение ничего не доказывает — надо дойти до конца.

### Вариант в одну строку и почему он хуже

```java
return Arrays.stream(nums).distinct().count() != nums.length;
```

Работает, читается за секунду, и на собеседовании его назвать стоит. Но как основной ответ он не годится, и причины интереснее, чем «стримы медленные».

**Досрочного выхода нет.** `count()` обязан пересчитать все различные значения, поэтому поток протягивается до конца, даже если дубликат стоял вторым. Проверено запуском на массиве из миллиона элементов, где дубликат на индексе 1:

```
distinct().count()  : ответ true, просмотрено элементов 1 000 000
цикл с HashSet      : ответ true, просмотрено элементов 2
```

**Внутри всё равно хеш-таблица, да ещё с упаковкой.** `IntStream.distinct()` в JDK реализован так:

```java
public final IntStream distinct() {
    // While functional and quick to implement, this approach is not very efficient.
    // An efficient version requires an int-specific map/set implementation.
    return boxed().distinct().mapToInt(i -> i);
}
```

Комментарий про неэффективность — из исходников JDK, не мой. Каждый `int` заворачивается в `Integer`, то есть к `O(n)` памяти добавляются ещё и объекты-обёртки.

**Задача-то про то, что внутри.** Интервьюер спрашивает не «знаешь ли ты Stream API», а «понимаешь ли ты, почему это `O(n)`». Однострочник прячет ровно ту часть, которую просят показать.

Если очень хочется потока — вот версия, которая всё-таки обрывается на первом же повторе, потому что `anyMatch` короткозамкнутый:

```java
Set<Integer> seenValues = new HashSet<>();
return Arrays.stream(nums).anyMatch(value -> !seenValues.add(value));
```

Проверено: на том же миллионном массиве она просматривает 2 элемента. Но это уже тот же цикл, просто записанный через поток — и побочный эффект внутри лямбды делает её спорной с точки зрения стиля.

## Свойства решения

| Характеристика | `containsDuplicate` |
|---|---|
| Структура | `HashSet` |
| Время, худший случай | `O(n)` в среднем — массив без повторов просматривается целиком |
| Время, лучший случай | `O(1)` — первые два элемента совпали |
| Память, худший случай | `O(n)` — до `n` значений в таблице, когда повторов нет |
| Память, лучший случай | `O(1)` — повтор нашёлся сразу, в множестве один элемент |
| Проходов по входу | один |
| Ранний выход | есть, на первом же повторе; на миллионе одинаковых элементов просматриваются два |
| Изменяет ли вход | нет |
| Требования к входу | никаких; сортировка не нужна и не делается — она стоила бы `O(n log n)` |
| Работа на потоке | да по природе: решение принимается по уже виденному. Потоковой версии в классе нет |
| Детерминированность | да |
| Устойчивость к деградации | `O(1)` у хеш-таблицы — амортизированная оценка в среднем: при большом числе коллизий операция деградирует |
| Ответ после цикла | `return false` — «дошли до конца, повторов не нашли»; одно уникальное значение ничего не доказывает, поэтому внутрь цикла этот `return` ставить нельзя |

Наивное решение для сравнения — перебор всех пар вложенным циклом: `O(n²)` времени и `O(1)` памяти. На `10^5` элементах это порядка `10^10` сравнений.
