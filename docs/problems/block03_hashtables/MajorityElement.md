# 169. Majority Element

*Мажоритарный элемент (дословно: элемент большинства)*

**Сложность:** Easy · **Паттерн:** счётчик частот, follow-up — голосование Бойера—Мура · **Классы:** `block03_hashtables.MajorityElement`, `block03_hashtables.MajorityElementBookVersion`

## Условие

Дан массив целых чисел `nums` длины `n`. Найти **мажоритарный элемент** — тот, который встречается **строго больше** `⌊n/2⌋` раз.

Гарантируется, что такой элемент в массиве есть и он единственный. Проверять его отсутствие не нужно.

Обрати внимание на «строго больше половины», а не «чаще всех». Это разные условия, и именно на первом держится весь алгоритм из follow-up.

## Примеры

### Пример 1

```
Вход:  nums = [3, 2, 3]
Выход: 3
```

Длина 3, порог `⌊3/2⌋ = 1`. Тройка встречается 2 раза, это больше единицы.

### Пример 2

```
Вход:  nums = [2, 2, 1, 1, 1, 2, 2]
Выход: 2
```

Длина 7, порог `⌊7/2⌋ = 3`. Двойка встречается 4 раза, единица — 3. Обрати внимание: единица встречается ровно `⌊n/2⌋` раз и мажоритарной **не** является.

### Пример 3

```
Вход:  nums = [1]
Выход: 1
```

Единственный элемент всегда мажоритарный: порог `⌊1/2⌋ = 0`.

## Ограничения

- `n == nums.length`
- `1 <= n <= 5 * 10^4`
- `-10^9 <= nums[i] <= 10^9`
- мажоритарный элемент существует и единственен

## Follow-up из условия

На LeetCode у задачи есть дополнительный вопрос, и он вшит в текст: решить за `O(n)` времени и `O(1)` **дополнительной памяти**.

Первое требование закрывает и обычный счётчик в хеш-таблице. Второе — нет: таблица хранит до `n` записей. Ради `O(1)` и нужен отдельный алгоритм.

## Идея решения

### Способ 1: счётчик частот

Прямое применение приёма блока. Проходим массив, копим в `HashMap` частоты, попутно запоминаем значение с наибольшим счётчиком.

```java
Map<Integer, Integer> counts = new HashMap<>();
int best = nums[0];
for (int value : nums) {
    int count = counts.merge(value, 1, Integer::sum);
    if (count > counts.get(best)) {
        best = value;
    }
}
return best;
```

`merge(value, 1, Integer::sum)` кладёт единицу, если ключа не было, и прибавляет её к существующему значению, если был. Возвращает новое значение — поэтому отдельный `get` после вставки не нужен.

Порог `n/2` тут проверять не требуется: по условию мажоритарный элемент существует, значит самый частый и есть ответ.

`O(n)` времени, `O(n)` памяти. Follow-up не закрыт.

### Способ 2: голосование Бойера—Мура

Алгоритм, ради которого задача и существует. Держим две переменные: `majority` — значение, которое сейчас считается возможным доминирующим, и `count` — сколько его вхождений ещё не погашено чужими.

```java
int majority = 0;
int count = 0;
for (int n : nums) {
    if (count == 0) {
        majority = n;
    }
    if (n == majority) {
        count++;
    } else {
        count--;
    }
}
return majority;
```

Три правила, и всё:

1. `count` упал до нуля — берём текущий элемент новым значением `majority`;
2. элемент равен `majority` — счётчик растёт;
3. не равен — счётчик падает.

`O(n)` времени, `O(1)` памяти. Follow-up закрыт.

Код воспроизведён из книги без изменений — имена переменных, развёрнутый `if/else`, инициализация нулём. Однобуквенное `n` в проекте обычно запрещено, но здесь оставлено намеренно: при сверке с книгой код должен читаться один в один.

Начальное `majority = 0` тоже оттуда, и оно лучше, чем `nums[0]`: на пустом массиве второй вариант падает с `ArrayIndexOutOfBoundsException`, а этот спокойно доходит до конца цикла, который просто не начинается. По ограничениям задачи пустого входа не бывает, но опираться на существование нулевого элемента там, где без этого можно обойтись, незачем.

### Откуда взялись эти названия

Алгоритм придумали Роберт Бойер и Джей Стротер Мур в 1981 году, и формулировали они его как **задачу о выборах**. Отсюда все термины, и они не метафора, а прямое описание исходной постановки.

**Мажоритарная избирательная система** — та, где для победы нужно абсолютное большинство, больше половины голосов. Не «больше всех», а именно больше половины. Отсюда и название задачи, и требование «строго больше `n/2`».

**Элемент массива** — один поданный голос. Массив `[2,2,1,1,1,2,2]` это бюллетени: два голоса за двойку, три за единицу, два за двойку.

**`majority`** — тот, кого мы сейчас считаем возможным победителем.

**`count`** — сколько голосов за него ещё не погашено чужими.

### Почему голосование работает

Представь, что избиратели стоят в очереди и **попарно выбивают друг друга**: подходит человек с чужим бюллетенем — он и один сторонник текущего фаворита взаимно уходят. `count` это сколько сторонников фаворита ещё стоит на площади.

Счётчик упал до нуля — сторонников не осталось, фаворит выбыл. Следующий человек в очереди объявляет фаворитом себя.

Прогон на `[2, 2, 1, 1, 1, 2, 2]`:

| шаг | голос | что происходит | `majority` | `count` |
|---|---|---|---|---|
| 0 | 2 | счётчик 0, двойка становится фаворитом | 2 | 1 |
| 1 | 2 | свой, встаёт рядом | 2 | 2 |
| 2 | 1 | чужой, выбивает одного | 2 | 1 |
| 3 | 1 | чужой, выбивает последнего | 2 | 0 |
| 4 | 1 | счётчик 0, единица становится фаворитом | 1 | 1 |
| 5 | 2 | чужой, выбивает | 1 | 0 |
| 6 | 2 | счётчик 0, двойка становится фаворитом | 2 | 1 |

Ответ — двойка.

Почему это обязано сработать: каждое выбивание уносит одного своего и одного чужого. Мажоритарный элемент занимает строго больше половины массива — значит чужих меньше, чем его. Даже если каждый чужой заберёт с собой одного сторонника большинства, чужие кончатся раньше. Хотя бы один сторонник большинства останется стоять, и в конце фаворитом окажется он.

Отсюда видно, почему условие «строго больше половины» принципиально. На массиве `[1, 1, 2, 2]` большинства нет вовсе, стороны сокращают друг друга полностью, и алгоритм вернёт какое-то значение — но оно ничего не будет означать.

**Значение `majority` по ходу цикла ответом быть не обязано.** Промежуточные значения могут быть любыми, гарантия относится только к состоянию после последней итерации. Это самая частая ошибка при чтении алгоритма.

### Когда большинства может не быть

Если гарантия из условия снята, добавляется второй проход: посчитать, сколько раз кандидат реально встречается, и сравнить с `n/2`. Памяти это не добавляет, время остаётся `O(n)`.

В самой задаче 169 такой проход не нужен, поэтому в решении его нет.

## Сложность

| | счётчик частот | голосование Бойера—Мура |
|---|---|---|
| Время | `O(n)` | `O(n)` |
| Память | `O(n)` | `O(1)` |
| Проходов по данным | один | один |
| Что хранит | до `n` записей в таблице | две переменные |
| Follow-up закрыт | нет | да |

Есть и третий способ, без кода: отсортировать массив и взять `nums[n / 2]`. Мажоритарный элемент занимает больше половины, поэтому середина обязана попасть в его блок. Решение в одну строку, но `O(n log n)` времени — назвать на собеседовании стоит, сдавать нет.

## Опора в книге

Задача 17.10 «Доминирующее значение» из главы «Сложные задачи». Условие на с. 191, решение на с. 586–589 (глава начинается на с. 190 в части с вопросами и на с. 560 в части с решениями). Тот же целевой алгоритм за `O(n)` времени и `O(1)` памяти. Поиск в RAG-файле: фраза «присутствующее более», в разборе решения — «доминирующим элементом».

Показательно, что в книге она отнесена к главе «Сложные задачи», а на LeetCode помечена как Easy. Easy тут про объём кода, а не про то, легко ли додуматься.

### Условие в книге строже

Ключевое отличие: **в книге не гарантируется, что доминирующее значение существует**. Если его нет, надо вернуть `-1`.

Из-за этого решение становится двухпроходным:

```java
int findMajorityElement(int[] array) {
    int candidate = getCandidate(array);
    return validate(array, candidate) ? candidate : -1;
}
```

`getCandidate` — то же голосование. `validate` — обычный подсчёт вхождений и сравнение с `array.length / 2`.

Второй проход обязателен именно потому, что `getCandidate` **всегда что-то возвращает**, даже когда доминирующего значения нет вовсе. Без проверки этот мусор ушёл бы в ответ.

Реализация обоих решений из книги, включая наивное `O(n²)`, с которого книга начинает рассуждение, — класс `block03_hashtables.MajorityElementBookVersion`.

Полезно держать в голове обе версии. На собеседовании гарантия «элемент точно есть» может как прозвучать в условии, так и не прозвучать — и уточнить это стоит до того, как писать код.
