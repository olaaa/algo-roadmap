# Паттерн «хеш-таблица за один проход» (hash map)

**Блок:** `block03_hashtables` · **Тип:** обзор паттерна (не отдельная задача)

Обзорная заметка по паттерну для всего блока. Разбор конкретных задач — в соседних файлах (`TwoSum.md` и последующих).

## В чём суть

Вместо того чтобы для каждого элемента перебирать все остальные вложенным циклом, ты один раз проходишь по данным и **запоминаешь увиденное в хеш-таблице**. Тогда вопрос «а встречался ли раньше нужный элемент?» решается не перебором, а мгновенной проверкой `containsKey` за амортизированное `O(1)`. Один проход + константная проверка на каждом шаге = `O(n)` вместо `O(n²)`.

Ключевая идея: хеш-таблица превращает вопрос «есть ли где-то среди уже пройденного элемент с таким-то свойством?» из линейного поиска в одну операцию. Ты платишь за это памятью — таблица хранит до `n` записей.

## Типовые формы

**Дополнение (complement).** Ищешь пару элементов с заданной суммой/разницей. Для текущего элемента вычисляешь, какое «дополнение» нужно, и проверяешь, не встречалось ли оно раньше. Классика — Two Sum на неотсортированном массиве. Кладёшь в таблицу *после* проверки, чтобы не спарить элемент сам с собой.

**Счётчик частот (frequency map).** Таблица `значение -> сколько раз встретилось`. Нужна для «сколько раз встречается X», «самый частый элемент», анаграммы (сравнение частот букв), «первый неповторяющийся символ».

**Множество виденного (seen set).** Таблица (или `HashSet`) как «видел / не видел». Классика — поиск дубликатов (Contains Duplicate): встретил элемент, которого нет в множестве — добавил; встретил уже лежащий — нашёл дубликат. В Java обе операции сливаются в одну: `add` возвращает `false`, если элемент уже был, поэтому пара `contains` + `add` не нужна.

**Группировка по ключу.** Таблица `ключ -> список элементов`. Классика — группировка анаграмм по «отпечатку» (отсортированные буквы слова как ключ). В Java список создаётся через `computeIfAbsent(key, absent -> new ArrayList<>())`: он находит список по ключу, а при отсутствии ключа создаёт его и кладёт в карту, поэтому связка `containsKey` + ручное создание не нужна.

Отличие этой формы от остальных: ключ не дан в условии, его надо **сконструировать**. Отсюда и правило — отпечаток обязан быть одинаковым у всех элементов группы и разным у элементов из разных групп. Проверка на неоднозначность здесь такая же обязательная часть решения, как сам алгоритм.

## Почему он работает в разных задачах

Общее свойство всех этих задач: **тебе нужно быстро отвечать на вопрос о принадлежности или частоте по ходу одного прохода.** Хеш-таблица даёт этот ответ за `O(1)`, поэтому наивный квадрат («для каждого элемента ищу среди всех остальных») схлопывается в линию («для каждого элемента спрашиваю у таблицы»).

Важное отличие от двух указателей: указателям нужна **упорядоченность** (отсортированный массив), а хеш-таблице порядок безразличен — она работает на «сыром» неотсортированном входе и сохраняет исходные индексы. Это ровно тот случай, когда сортировать нельзя или дорого.

## Как распознать, что нужен именно он

Сигналы, по которым на собеседовании стоит подумать про хеш-таблицу (в скобках — опорный класс из этого блока):

1. Задача про пару элементов с суммой/разницей, но массив **не отсортирован** и сортировать нельзя (важны исходные индексы). → `TwoSum`
2. Наивное решение — двойной вложенный цикл `O(n²)` «для каждого ищу подходящий среди остальных», и его просят ускорить, а упорядоченности для двух указателей нет. → `TwoSum`
3. Нужно посчитать **частоты**: сколько раз встречается элемент, самый частый, первый уникальный, сравнение анаграмм. → *класса пока нет (частоты ещё не реализованы)*
4. Нужно проверить **наличие дубликатов** / «видел ли я это раньше». → `ContainsDuplicate`
5. Нужно **сгруппировать** элементы по общему ключу. → `GroupAnagrams`

Быстрая эвристика для интервью: *вижу вложенный цикл «для каждого элемента ищу что-то среди остальных» + порядок не важен или его нет → пробую хеш-таблицу и меняю время на память.*

## Trade-off, который надо проговорить

Хеш-таблица — это всегда обмен памяти на скорость: `O(n)` дополнительной памяти ради `O(n)` времени вместо `O(n²)`. На собеседовании это стоит назвать вслух: «я разменяю память на скорость». Если память критична, а массив можно сортировать — это, наоборот, аргумент в пользу двух указателей.

## Частая путаница

Хеш-таблица не «волшебно бесплатна»: `containsKey`/`put` — это `O(1)` **амортизированно**, в среднем. В худшем случае (плохие хеши, много коллизий) операция деградирует. На практике для `Integer`/`String` в Java это не проблема, но на собеседовании корректно говорить именно «амортизированное `O(1)`», а не «строго `O(1)`».
