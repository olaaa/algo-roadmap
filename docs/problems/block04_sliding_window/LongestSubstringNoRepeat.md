# 3. Longest Substring Without Repeating Characters

*Самая длинная подстрока без повторяющихся символов*

**Сложность:** Medium · **Паттерн:** скользящее окно переменной ширины · **Класс:** `block04_sliding_window.LongestSubstringNoRepeat`

## Условие

Дана строка `s`. Найти длину самой длинной **подстроки**, в которой ни один символ не повторяется.

В самом условии LeetCode пояснения к термину нет, а к примеру 3 приписано: «`"pwke"` is a subsequence and not a substring». На этом различии в задаче стоит ловушка, поэтому разберём его до примеров.

## Подстрока и подпоследовательность

Оба слова означают «взять часть строки». Разница в том, **какие позиции разрешено брать**.

- Подстрока (`substring`) — отрезок: берём позиции подряд, от `i` до `j`, ни одной не оставляя внутри.
- Подпоследовательность (`subsequence`) — набор: берём любые позиции, лишь бы порядок слева направо сохранялся. Между взятыми могут оставаться невзятые.

Отрезок — частный случай набора: любая подстрока является подпоследовательностью, обратное неверно.

### Что называется пропуском

Пропуск — это **невзятая позиция исходной строки, у которой есть взятые и слева, и справа**. Дырка не в получившемся слове (оно всегда написано слитно), а в наборе выбранных позиций.

Видно на выборе `"pwke"` из строки `"pwwkew"`:

```
позиция:   0     1     2     3     4     5
строка:    p     w     w     k     e     w
берём:    да    да   [нет]   да    да   нет
                       ^
                       эта позиция не взята,
                       а взятые есть и слева (1), и справа (3)
                       значит это пропуск
```

Позиция 5 тоже не взята, но пропуском не считается: справа от неё взятых уже нет, набор к тому моменту закончился. Пропуск — только дырка ВНУТРИ выбора.

### Та же строка, три разбора

```
позиция:   0   1   2   3   4   5
строка:    p   w   w   k   e   w
```

Подстрока `"wke"` — позиции 2, 3, 4 подряд:

```
позиция:   0   1   2   3   4   5
строка:    p   w  [w   k   e]  w
                  ^^^^^^^^^^^
                  сплошной отрезок, дырок внутри нет
                  значит ПОДСТРОКА (и подпоследовательность заодно)
```

Подпоследовательность `"pwke"` — позиции 0, 1, 3, 4:

```
позиция:   0   1   2   3   4   5
строка:   [p] [w]  w  [k] [e]  w
                   ^
                   позиция 2 не взята, а вокруг неё взятые
                   значит ПОДПОСЛЕДОВАТЕЛЬНОСТЬ, подстрокой не является
```

Подстрока `"kew"` — позиции 3, 4, 5 подряд:

```
позиция:   0   1   2   3   4   5
строка:    p   w   w  [k   e   w]
                      ^^^^^^^^^^^
                      снова сплошной отрезок, значит ПОДСТРОКА
```

### Самый маленький пример, где видна разница

Строка `"abc"`. Выпишем всё, что из неё можно получить, пустой вариант опустим.

```
выбор     что вышло   позиции   есть дырка?   это что
--------------------------------------------------------------------
a         "a"         0          нет          подстрока
b         "b"         1          нет          подстрока
c         "c"         2          нет          подстрока
a b       "ab"        0,1        нет          подстрока
b c       "bc"        1,2        нет          подстрока
a b c     "abc"       0,1,2      нет          подстрока
a _ c     "ac"        0,2        ДА (поз. 1)  только подпоследовательность
```

Шесть подстрок и семь подпоследовательностей, разница ровно в одной строке таблицы — `"ac"`. Это единственный выбор, где между взятыми позициями осталась невзятая.

Отсюда же видно, почему подпоследовательностей всегда больше: каждая позиция независимо решает «беру / не беру», это `2^n` вариантов, а непустых отрезков всего `n · (n + 1) / 2`. На строке из двадцати символов это миллион с лишним против двухсот десяти.

### Как проверить себя за пять секунд

Выпиши номера взятых позиций через запятую и посмотри, идут ли они подряд.

```
"wke"    2, 3, 4      подряд, шаг всегда 1   значит подстрока
"pwke"   0, 1, 3, 4   между 1 и 3 разрыв     значит подпоследовательность
```

### Житейская аналогия

Подстрока — вырезать кусок ленты **двумя разрезами**. Что было между разрезами, то и получил, выбросить букву из середины нельзя.

Подпоследовательность — идти по ленте слева направо и **переписывать** буквы в блокнот, какие-то пропуская. В блокноте они окажутся слитно, но на ленте между ними остались дырки.

Путаница ровно отсюда: в блокноте `"pwke"` выглядит сплошным словом, и дырка видна, только если смотреть на исходную ленту.

### Почему это важно для решения

Скользящее окно умеет **только подстроки**. Окно — это две границы, между которыми лежит сплошной отрезок; пропустить элемент в середине оно физически не может.

Поэтому в условии первым делом ищут слово `substring` или `subarray` («подстрока», «подмассив», «непрерывный участок»). Если написано `subsequence`, окно неприменимо в принципе и задача решается другими средствами, обычно динамическим программированием.

## Примеры

### Пример 1

```
Вход:  s = "abcabcbb"
Выход: 3
```

Лучшая подстрока — `"abc"`, длина 3. Дальше начинаются повторы.

### Пример 2

```
Вход:  s = "bbbbb"
Выход: 1
```

Все символы одинаковые, окно шире одного символа не бывает.

### Пример 3

```
Вход:  s = "pwwkew"
Выход: 3
```

Ответ — `"wke"` (позиции 2, 3, 4), а не `"pwke"`. Второе собрано из позиций 0, 1, 3, 4: позиция 2 в него не входит, символы не идут подряд, и подстрокой такой выбор не является — разбор выше.

### Пример 4

```
Вход:  s = ""
Выход: 0
```

Пустая строка допустима, цикл не начинается ни разу.

## Ограничения

- `0 <= s.length <= 10^5`
- `s` состоит из английских букв, цифр, знаков и пробелов

Обрати внимание на два места. Длина может быть нулевой — пустая строка входит в допустимые данные, а не является краевым случаем «на всякий случай». И алфавит ограничен печатными ASCII-символами: экзотических кодировок в задаче нет.

## Почему такие ограничения

`10^5` отсекают наивное решение. Наивное перебирает все начала и все концы, для каждой подстроки проверяя уникальность, — это `O(n³)`. Даже улучшенный вариант, где уникальность проверяется множеством по ходу, остаётся `O(n²)`, а это `10^10` операций на предельном входе.

Ограничение на алфавит важно для выбора структуры под состояние окна и для оценки памяти: разных символов не больше размера алфавита, сколь бы длинной ни была строка.

## Идея решения

Окно — это участок строки, в котором **нет повторов**. Это его инвариант, и всё решение построено вокруг того, чтобы инвариант держался.

Правая граница двигается на каждом шаге и **расширяет** окно. Нарушить инвариант может только входящий символ: если он в окне уже есть, появляется повтор. Тогда левая граница **сжимает** окно, выбрасывая символы слева по одному, пока повтор не исчезнет.

Ответ обновляется в конце итерации, когда окно снова корректно.

```java
Set<Character> windowChars = new HashSet<>();
int longestLength = 0;
int windowStart = 0;

for (int windowEnd = 0; windowEnd < text.length(); windowEnd++) {
    char enteringChar = text.charAt(windowEnd);
    while (windowChars.contains(enteringChar)) {
        windowChars.remove(text.charAt(windowStart));
        windowStart++;
    }
    windowChars.add(enteringChar);
    longestLength = Math.max(longestLength, windowChars.size());
}
return longestLength;
```

Про сам приём — [`Pattern_SlidingWindow.md`](Pattern_SlidingWindow.md), подвид «окно переменной ширины».

### Почему длина считается после цикла сжатия

Порядок трёх действий внутри итерации не произволен:

1. сжать окно, пока входящий символ в нём есть;
2. добавить входящий символ;
3. измерить длину.

Если измерить до сжатия, длина будет посчитана на окне с повтором — то есть на участке, который ответом быть не может. Это [приём 8 из шпаргалки](../../heuristics.md#8-восстанови-инвариант-до-того-как-измеришь-результат).

### Чем измеряется длина окна

Способов два, и они дают одно и то же число — но только в решении с множеством.

**Через размер множества.** `windowChars.size()` — так написано в коде. Работает потому, что множество и окно совпадают по содержимому: это инвариант метода, который держится симметрией «вошёл `add` — вышел `remove`». Раз в окне нет повторов, каждый его символ лежит в множестве ровно один раз, значит размер множества и есть длина окна.

**Через границы.** `windowEnd - windowStart + 1` — арифметика по индексам, размер структуры не нужен.

Плюс единица здесь потому, что **обе границы включены** в окно. Без неё считалось бы расстояние между границами, а не количество символов:

```
позиция:   0   1   2   3   4
окно:          [b   c   d]
               ^        ^
        windowStart = 1  windowEnd = 3

3 - 1     = 2   ← шаг от b до d, символы посчитаны неверно
3 - 1 + 1 = 3   ← b, c, d, три символа
```

Проверить себя проще всего на окне из одного символа: `windowStart` равен `windowEnd`, разность нулевая, а длина обязана быть единицей.

### Почему в варианте с прыжком размер структуры не годится

Это не вопрос вкуса: там `lastSeenIndex.size()` дал бы **неверный** ответ. Карта помнит все виденные символы, в том числе покинувшие окно, поэтому её размер — это число различных символов всей просмотренной части строки, а не длина окна.

Контрпример — `"aabbccdd"`. Различных символов четыре, а самое длинное окно без повторов — `"ab"`, длина 2. Размер карты в конце вернул бы 4.

Отсюда общее правило: размером структуры длину окна мерить можно только тогда, когда структура точно повторяет окно. Как только в состоянии заводятся записи, переживающие выход элемента, остаётся арифметика по границам.

### Почему `Math.max`, а не присваивание

Длина окна не растёт монотонно: после сжатия окно становится короче предыдущего. На строке `"abcb"` окно проходит длины 1, 2, 3, а затем сжимается до 2. Простое присваивание затёрло бы тройку двойкой, хотя подстрока `"abc"` уже встретилась и является ответом.

Максимум поэтому накапливается, а не переприсваивается.

### Два способа сдвинуть левую границу

**По одному символу.** Тот, что выше: `while` выбрасывает символы слева, пока повтор не уйдёт. Состояние — множество символов окна, и симметрия соблюдена буквально: вошёл — `add`, вышел — `remove`.

**Прыжком.** Вместо множества карта «символ → последняя позиция». Тогда при повторе левую границу можно поставить сразу за прошлым вхождением, без цикла:

```java
Integer previousIndex = lastSeenIndex.get(enteringChar);
if (previousIndex != null) {
    windowStart = Math.max(windowStart, previousIndex + 1);
}
lastSeenIndex.put(enteringChar, windowEnd);
```

Оба варианта реализованы в классе и прогнаны на одинаковых тестах: `lengthOfLongestSubstring` и `lengthOfLongestSubstringWithJump`.

### Ловушка варианта с прыжком: граница не пятится назад

`Math.max` в строке `windowStart = Math.max(windowStart, previousIndex + 1)` — не украшение. Карта помнит **все** виденные символы, включая те, что окно уже покинули. Без `Math.max` левая граница прыгнула бы назад, к позиции символа вне окна, и в окно вернулись бы уже выброшенные символы.

Опорный пример — `"abba"`:

```
позиция:      0   1   2   3
символ:       a   b   b   a
```

На позиции 3 входит `a`, её прошлая позиция в карте — 0. Но окно к этому моменту уже начинается с позиции 2 (его сжало повторное `b`). Без `Math.max` получилось бы `windowStart = 1`, окно `"bba"` — с повтором внутри, и ответ 3 вместо правильного 2.

В варианте с множеством этой ловушки нет вовсе: там нельзя выбросить символ, которого в окне не было.

### Ловушка обоих вариантов: сброс окна на текущую позицию

Соблазнительная ошибка — при обнаружении повтора начать окно заново, поставив `windowStart = windowEnd`. Ломается на `"dvdf"`: при повторном `d` (позиция 2) окно должно стать `"vd"`, а сброс дал бы `"d"`, дальше `"df"`, и ответ вышел бы 2 вместо 3. Повтор выбрасывает только часть окна — ту, что слева от прошлого вхождения включительно, а не всё окно.

### Почему это `O(n)`, несмотря на вложенный `while`

Вопрос почти гарантированный. Считать надо не вложенность циклов, а сколько раз сдвигается каждая граница за весь прогон.

Правая проходит строку ровно один раз — `n` шагов. Левая двигается только вперёд и никогда не обгоняет правую, значит суммарно тоже не больше `n` шагов. Всего не больше `2n` сдвигов, каждый за `O(1)`.

Это [амортизационный анализ](Pattern_SlidingWindow.md#почему-обе-границы-вместе-дают-on), и назвать его вслух — сильный ход на собеседовании.

### Про тип символа

Состояние окна хранится по ключу `char`. Ограничения задачи — английские буквы, цифры, знаки и пробелы, то есть ASCII, и на них `char` заведомо годится.

Тестами дополнительно проверены 512 различных значений `char`, то есть решение работает не только на ASCII. Но за пределы BMP оно не выходит: символы вроде эмодзи хранятся в Java суррогатной **парой** `char`, и такого теста нет — значит и обещания такого решение не даёт. Разбор этой ловушки на соседней задаче — в [`FirstUniqueChar.md`](../block02_strings_stack/FirstUniqueChar.md).

## Свойства решений

Сложность по времени и памяти — не единственные характеристики алгоритма, и на собеседовании спрашивают не только их. Сводка по обоим методам класса.

| Характеристика | `lengthOfLongestSubstring` (множество) | `lengthOfLongestSubstringWithJump` (карта позиций) |
|---|---|---|
| Время, худший случай | `O(n)` | `O(n)` |
| Фактическое число операций | до `2n` шагов границ: каждый символ один раз входит и один раз выходит | ровно `n` итераций, внутреннего цикла нет |
| Время, лучший случай | `O(n)` — вход всё равно просматривается целиком | `O(n)`, там же |
| Память | `O(min(n, размер алфавита))` — в множестве только символы окна | `O(min(n, размер алфавита))` — в карте все различные символы строки, включая покинувшие окно |
| Пик памяти на практике | не больше длины самого длинного окна | не меньше, чем у множества: записи не удаляются |
| Число проходов по входу | один | один |
| Ранний выход | нет: более длинное окно может встретиться дальше, поэтому строка досматривается до конца | нет, по той же причине |
| Изменяет ли вход | нет, `String` неизменяема, обе функции чистые | нет |
| Нужен ли доступ к будущему | нет: решение принимается по уже просмотренному | нет |
| Детерминированность | да, случайности нет | да |
| Требования к входу | никаких: сортировка и предобработка не нужны | никаких |
| Симметрия состояния | полная: вошёл `add`, вышел `remove` | неполная: запись о символе остаётся навсегда, поэтому нужен `Math.max` |
| Где легче ошибиться | почти негде: выбросить символ, которого в окне нет, невозможно | в `Math.max`: без него граница пятится назад (`"abba"`) |

Оценка памяти опирается на наблюдение из книги (см. ниже): строка не может содержать больше уникальных символов, чем есть в алфавите. Поэтому на ASCII память фактически `O(1)` — не больше 128 ключей, сколь бы длинной ни была строка.

Наивное решение для сравнения: `O(n²)`, если проверять уникальность множеством по ходу, и `O(n³)` без него.

Итог: по асимптотике методы неразличимы, разница в константе и в надёжности. Вариант с прыжком делает меньше операций, вариант с множеством труднее сломать.

### Что ещё бывает у алгоритмов

Не все характеристики применимы к этой задаче, но спросить могут про любую:

- **Устойчивость (stability)** — сохраняется ли исходный порядок равных элементов. Свойство сортировок; здесь неприменимо, ничего не сортируется.
- **Адаптивность** — ускоряется ли алгоритм на «хорошем» входе (уже почти отсортированном). Тоже про сортировки.
- **Онлайновость** — можно ли обрабатывать поток, выдавая ответ для каждого префикса. Оба алгоритма по природе онлайновые: ни один не заглядывает вперёд. Но методы класса принимают готовую `String`, потоковой версии в нём нет, и тестами такое использование не проверено.
- **Рандомизированность** — использует ли алгоритм случайность (быстрая сортировка со случайной опорой, хеширование с солью).
- **Завершаемость** — доказуемо ли, что алгоритм остановится. Здесь доказывается в одну строку: `windowEnd` растёт на каждой итерации и ограничен длиной строки, `windowStart` не убывает и не обгоняет `windowEnd`.
- **Устойчивость к деградации** — насколько плох худший случай по сравнению со средним. У хеш-структур `O(1)` — амортизированная и средняя оценка: при массовых коллизиях операция деградирует, и на собеседовании это оговаривают вслух. Подробнее — в [`Pattern_HashMap.md`](../block03_hashtables/Pattern_HashMap.md).

Задача 1.1 «Уникальные символы» из главы 1 «Массивы и строки» (вопросы — с. 82, решения — с. 197). Там спрашивается проще: все ли символы строки уникальны, ответ да/нет по всей строке. Но два рассуждения оттуда переносятся сюда целиком.

Первое — состояние «что уже виделось» держится в массиве флагов или множестве, и проверка вхождения стоит `O(1)`.

Второе — сравнение длины строки с размером алфавита: строка из 280 символов при алфавите в 128 обязана содержать повтор. В нашей задаче из этого следует оценка памяти и потолок ответа. Поиск в RAG-файле: фраза «все ли символы в строке».
