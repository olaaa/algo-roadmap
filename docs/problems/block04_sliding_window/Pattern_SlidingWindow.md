# Паттерн «скользящее окно» (sliding window)

**Блок:** `block04_sliding_window` · **Тип:** обзор паттерна (не отдельная задача)

Обзорная заметка по паттерну для всего блока. Разбор конкретных задач — в соседних файлах (`MaxAverageSubarray.md` и последующих).

## В чём суть

Задача просит найти **непрерывный участок** массива или строки, удовлетворяющий условию: подмассив длины `k` с максимальной суммой, самая длинная подстрока без повторов, кратчайший отрезок с суммой не меньше заданной.

Наивное решение перебирает все участки: внешний цикл выбирает начало, внутренний конец, и для каждого участка что-то считается заново. Это `O(n²)`, а с пересчётом суммы внутри — и `O(n³)`.

Ключевое наблюдение: **соседние участки почти совпадают**. Если окно сдвинулось на одну позицию, из него вышел ровно один элемент и вошёл ровно один. Значит характеристику участка не надо считать с нуля — её достаточно **обновить на разницу**.

Отсюда весь приём: держим границы окна и его состояние (сумма, счётчики символов, множество виденного), а на каждом шаге делаем два действия — «элемент вошёл» и «элемент вышел». Один проход, `O(n)`.

## Два подвида

Разница в том, **чем управляется правая и левая граница**.

### Окно фиксированной ширины

Ширина задана в условии числом `k`. Обе границы двигаются синхронно, шаг в шаг: вошёл элемент на правой границе, вышел элемент, стоявший на левой.

Отдельная переменная под левую границу не нужна — она вычисляется из правой:

```java
int windowStart = windowEnd - k;
windowSum = windowSum + nums[windowEnd] - nums[windowStart];
```

Цикл при этом обычно один: сначала набирается первое окно, потом оно едет до конца массива. Опорный класс — `MaxAverageSubarray`.

### Окно переменной ширины

Ширина заранее неизвестна, её диктует условие задачи: «без повторов», «сумма не больше X», «не более двух различных символов».

Правая граница двигается всегда, на каждой итерации внешнего цикла — она **расширяет** окно. Левая двигается только тогда, когда условие нарушено, и **сжимает** окно, пока нарушение не исчезнет.

```java
for (int windowEnd = 0; windowEnd < n; windowEnd++) {
    /* Элемент вошёл: обновляем состояние. */
    while (условие нарушено) {
        /* Элемент вышел: откатываем состояние. */
        windowStart++;
    }
    /* Окно корректно, обновляем ответ. */
}
```

Опорный класс — `LongestSubstringNoRepeat`, разбор в [`LongestSubstringNoRepeat.md`](LongestSubstringNoRepeat.md). Там же второй способ сдвинуть левую границу: вместо цикла сжатия карта последних позиций, и граница прыгает сразу за прошлое вхождение.

## Почему обе границы вместе дают `O(n)`

Вопрос, который любят задавать: «внутри `for` стоит `while`, разве это не квадрат?»

Нет. Считать надо не вложенность, а **сколько раз каждая граница сдвигается за весь прогон**. Правая проходит массив ровно один раз. Левая тоже движется только вперёд и не может уйти дальше правой — то есть суммарно тоже не больше `n` шагов.

Всего не больше `2n` сдвигов, каждый за `O(1)`. Это `O(n)`, несмотря на вложенный цикл. Такой способ рассуждения называется **амортизационным анализом**, и назвать его вслух на собеседовании — сильный ход.

## Как распознать, что нужен именно он

Сигналы (в скобках — опорный класс блока):

1. В условии есть слово **«подмассив», «подстрока», «непрерывный участок»** — не «подпоследовательность»! Подпоследовательность допускает пропуски, и окно там не работает. → `MaxAverageSubarray`
2. Задана **фиксированная длина участка** `k`, спрашивается максимум или минимум характеристики. → `MaxAverageSubarray`
3. Ищется **самый длинный или самый короткий** участок с ограничением на его содержимое. → `LongestSubstringNoRepeat`
4. Наивное решение — двойной цикл «для каждого начала перебрать все концы», и просят ускорить.
5. Характеристику участка можно **пересчитать за `O(1)`** при сдвиге на одну позицию: сумма, количество, максимум частоты.

Быстрая эвристика: *непрерывный участок + характеристика, обновляемая на разницу → окно.*

## Чем отличается от двух указателей

Формально окно — это тоже два индекса, и подвид «однонаправленное движение» из [`Pattern_TwoPointers.md`](../block01_arrays_twopointers/Pattern_TwoPointers.md) выглядит похоже. Разница в том, что несут указатели.

У двух указателей это **две независимые позиции**: читающая и пишущая, начало и конец отрезка, быстрый и медленный. Между ними нет смысла «отрезок, который мы рассматриваем».

У окна два индекса — это **границы одного объекта**, и вместе с ними живёт **состояние этого объекта**: сумма, счётчики, множество. Именно состояние и отличает приём: его надо аккуратно обновлять на входе и откатывать на выходе.

## Частые ловушки

**Подпоследовательность вместо подмассива.** Если участок не обязан быть непрерывным, окно неприменимо в принципе. Проверять это надо до того, как начал писать код.

**Забыть откатить состояние при сдвиге левой границы.** Симметрия «вошёл — вышел» обязана соблюдаться: если на входе прибавили, на выходе надо вычесть; если увеличили счётчик, надо уменьшить.

**Считать ответ до того, как окно стало корректным.** В окне переменной ширины ответ обновляется **после** цикла сжатия, а не до и не внутри.

**Целочисленное деление при подсчёте среднего.** Если сумма и длина оба `int`, деление даст `int`, и дробная часть потеряется молча. Разбор — в [`MaxAverageSubarray.md`](MaxAverageSubarray.md).

**Переполнение суммы.** Сумма окна на длинном массиве может не влезть в `int`. Ограничения задачи стоит перемножить в уме до того, как выбирать тип.
