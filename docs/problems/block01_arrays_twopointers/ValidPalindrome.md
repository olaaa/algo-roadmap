# 125. Valid Palindrome
*Проверка на палиндром (дословно: корректный палиндром)*

**Сложность:** Easy · **Паттерн:** два указателя · **Класс:** `block01_arrays_twopointers.ValidPalindrome`

## Условие

Строка называется **палиндромом**, если после приведения всех заглавных букв к строчным и удаления всех символов, кроме букв и цифр, она читается одинаково слева направо и справа налево.

Дана строка `s`. Вернуть `true`, если `s` — палиндром по этому правилу, иначе `false`.

Иными словами: рассматриваем только буквенно-цифровые символы (буквы и цифры), регистр игнорируем; всё остальное (пробелы, знаки препинания) пропускаем.

## Примеры

### Пример 1

```
Вход:  s = "A man, a plan, a canal: Panama"
Выход: true
```

После чистки получаем `"amanaplanacanalpanama"` — палиндром.

### Пример 2

```
Вход:  s = "race a car"
Выход: false
```

После чистки получаем `"raceacar"` — не палиндром.

### Пример 3

```
Вход:  s = " "
Выход: true
```

После удаления не-буквенно-цифровых символов остаётся пустая строка `""`. Пустая строка читается одинаково в обе стороны, поэтому это палиндром.

## Ограничения

- `1 <= s.length <= 2 * 10^5`
- `s` состоит из печатаемых символов ASCII

## Идея решения

Указатель слева (`leftIndex`) и справа (`rightIndex`) идут навстречу. Пропускаем всё, что не буква и не цифра. Сравниваем символы в нижнем регистре: не совпали — сразу возвращаем `false`. Дошли до середины без расхождений — это палиндром.

Строку не копируем и отдельно не чистим — лишние символы игнорируем прямо на ходу.

### Что делает каждая переменная

| Переменная | Что хранит | Зачем она нужна |
|---|---|---|
| `s` | вход, строка целиком, вместе с пробелами и знаками | только читается: `String` в Java неизменяема, да и чистить её не требуется — мусор пропускается на ходу |
| `leftIndex` | позицию слева, с которой идёт сравнение | движется только вправо; растёт и при пропуске мусора, и после успешного сравнения пары |
| `rightIndex` | позицию справа | движется только влево, симметрично левому. Начинается с `s.length() - 1` — последний символ строки |

Переменной под «очищенную строку» здесь нет намеренно, и это главное решение задачи: она стоила бы `O(n)` памяти. Вместо неё — два индекса, которые сами перешагивают ненужное.

Отдельной переменной под символ тоже нет: `s.charAt(leftIndex)` вызывается прямо в условии. На двух вызовах за итерацию это дешевле, чем заводить и поддерживать ещё две переменные.

### Вложенный while или if + continue

Пропуск мусорных символов в решении оформлен вложенным `while`:

```java
while (leftIndex < rightIndex) {
    while (leftIndex < rightIndex && !Character.isLetterOrDigit(s.charAt(leftIndex))) {
        leftIndex++;
    }
    ...
}
```

Условие `leftIndex < rightIndex` во внутреннем цикле — не повтор рабочего условия, а защитная проверка (guard): на строке из одних знаков препинания промотка без неё убежала бы за встречный указатель и за пределы строки.

Тот же пропуск можно записать через `if` + `continue` — досрочное завершение одного прохода внешнего цикла:

```java
while (leftIndex < rightIndex) {
    if (!Character.isLetterOrDigit(s.charAt(leftIndex))) {
        leftIndex++;
        continue;   // заново на начало внешнего цикла
    }
    if (!Character.isLetterOrDigit(s.charAt(rightIndex))) {
        rightIndex--;
        continue;
    }
    ...сравнение...
}
```

Повтор пропуска здесь обеспечивает сам внешний цикл, а защита границ достаётся бесплатно — после `continue` условие `leftIndex < rightIndex` проверяется заново. Оба варианта корректны и равноценны; вложенный `while` компактнее выражает намерение «промотай весь мусор», вариант с `continue` избавляет от дублирования условия.

Аналогия для цикла `for` — `continue`-guard первой строкой тела, отсеивающий неподходящие элементы до основной обработки:

```java
for (int index = 0; index < items.length; index++) {
    if (!isRelevant(items[index])) {
        continue;
    }
    /* Обработка без вложенности */
}
```

## Свойства решения

| Характеристика | Значение |
|---|---|
| Время, худший случай | `O(n)` — строка-палиндром: сравниваются все пары до середины |
| Время, лучший случай | `O(1)` — первая же пара символов не совпала, ответ готов |
| Память | `O(1)` — два индекса; строка не нормализуется и не копируется |
| Проходов по входу | один, встречное движение; вложенный `while` не делает его квадратным — каждый указатель проходит строку не больше раза |
| Ранний выход | есть: `return false` при первом же несовпадении пары |
| Изменяет ли вход | нет; `String` в Java неизменяема, менять её и нечем |
| Требования к входу | никаких, любые символы допустимы — мусорные пропускаются на ходу |
| Работа на потоке | невозможна: сравнение идёт с двух концов сразу |
| Детерминированность | да |
| Завершаемость | на каждой итерации хотя бы один указатель сдвигается навстречу другому |
| Вырожденные входы | пустая строка и строка из одних знаков препинания — палиндромы; цикл завершается, не сравнив ни одной пары |

Альтернатива для сравнения: собрать очищенную строку в `StringBuilder`, развернуть и сравнить. Время тоже `O(n)`, но память становится `O(n)` — появляется копия строки.
