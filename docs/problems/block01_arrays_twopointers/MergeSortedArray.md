# 88. Merge Sorted Array
*Слияние отсортированных массивов (дословно: слить отсортированные массивы)*

**Сложность:** Easy · **Паттерн:** два указателя (с конца) · **Класс:** `block01_arrays_twopointers.MergeSortedArray`

## Условие

Даны два целочисленных массива `nums1` и `nums2`, оба отсортированы в **неубывающем** порядке. Даны также два числа `nums1Count` и `nums2Count` — количество значимых (реальных) элементов в `nums1` и `nums2` соответственно.

Нужно **слить** `nums2` в `nums1` так, чтобы получившийся массив был отсортирован в неубывающем порядке.

> **Неубывающий порядок** — нестрогий: каждый следующий элемент не меньше предыдущего (`a[i+1] >= a[i]`), то есть равные соседи допускаются (например, `1, 2, 2, 3`). Это отличается от **возрастающего** (строгого) порядка, где каждый следующий элемент строго больше (`a[i+1] > a[i]`, без повторов). В оригинале задачи стоит именно «non-decreasing», потому что в массивах возможны дубликаты.

Результат должен лежать **не** в новом массиве, а прямо в `nums1` (in-place, слияние «на месте»). Чтобы для результата хватило места, длина `nums1` равна `nums1Count + nums2Count`: первые `nums1Count` позиций — значимые элементы, а последние `nums2Count` позиций заполнены нулями-заглушками (их нужно перезаписать). Длина `nums2` равна `nums2Count`.

## Примеры

### Пример 1

```
Вход:  nums1 = [1, 2, 3, 0, 0, 0], nums1Count = 3
       nums2 = [2, 5, 6],          nums2Count = 3
Выход: [1, 2, 2, 3, 5, 6]
```

Сливаем `[1, 2, 3]` и `[2, 5, 6]` в один отсортированный массив `[1, 2, 2, 3, 5, 6]`.

### Пример 2

```
Вход:  nums1 = [1], nums1Count = 1
       nums2 = [],  nums2Count = 0
Выход: [1]
```

Сливать нечего — `nums1` уже готов.

### Пример 3

```
Вход:  nums1 = [0], nums1Count = 0
       nums2 = [1], nums2Count = 1
Выход: [1]
```

У `nums1` нет значимых элементов; единственный `0` — заглушка, перезаписываем его единицей из `nums2`.

## Ограничения

- `nums1.length == nums1Count + nums2Count`
- `nums2.length == nums2Count`
- `0 <= nums1Count, nums2Count <= 200`
- `1 <= nums1Count + nums2Count <= 200`
- `-10^9 <= nums1[i], nums2[j] <= 10^9`

## Идея решения

Наивно — сливать с начала, но тогда, записывая результат в начало `nums1`, мы затрём ещё не использованные значимые элементы самого `nums1`.

Поэтому заполняем `nums1` **с конца**: самый большой из оставшихся элементов кладём в самую правую свободную позицию и движемся к началу. Хвост `nums1` как раз свободен (там заглушки), так что ничего важного не затираем.

На каждом шаге сравниваем `nums1[firstIndex]` и `nums2[secondIndex]`, больший пишем в `writeIndex` и сдвигаем соответствующий указатель влево. Когда `nums2` закончился (`secondIndex < 0`) — всё, что осталось в `nums1`, уже на своих местах.

### Что делает каждая переменная

| Переменная | Что хранит | Зачем она нужна |
|---|---|---|
| `nums1` | вход и одновременно результат | сюда пишется ответ, поэтому массив и приходит с запасом в хвосте |
| `nums1Count` | сколько в `nums1` ЗНАЧИМЫХ элементов | длина массива на это не отвечает: в хвосте лежат нули-заглушки, и без счётчика их не отличить от настоящих нулей |
| `nums2` | второй вход, донор | только читается, не меняется |
| `nums2Count` | сколько элементов в `nums2` | по нему считается стартовая позиция чтения и определяется момент остановки |
| `firstIndex` | позицию последнего НЕобработанного элемента `nums1` | указатель чтения по приёмнику; уходит влево по мере переноса |
| `secondIndex` | позицию последнего необработанного элемента `nums2` | указатель чтения по донору; именно его исчерпание завершает цикл |
| `writeIndex` | позицию, куда ляжет следующий элемент | указатель записи; стартует с самого конца `nums1`, потому что заполняем от большего к меньшему |

Три указателя, а не два, именно потому, что источников два, а приёмник — третья сущность. В `MoveZeroes` из этого же блока хватает двух: там источник и приёмник — один массив.

Стартовые значения все со сдвигом на единицу: `nums1Count - 1`, `nums2Count - 1`, `nums1Count + nums2Count - 1`. Причина одна и та же — индексация с нуля, поэтому последний элемент лежит на позицию левее количества.

### Как придумать условие цикла (общий приём)

Условие цикла — это ответ на вопрос «когда работа ещё НЕ закончена?». Идёшь от обратного: сначала формулируешь, когда можно остановиться и результат уже корректен, а потом берёшь отрицание.

Часто корректны сразу несколько условий. Здесь верны все три: `writeIndex >= 0` («пока есть куда писать» — самое честное), `firstIndex >= 0 || secondIndex >= 0` («пока хоть где-то остались элементы») и минимальное `secondIndex >= 0` — потому что остатки `nums1` уже стоят на своих местах, а остатки `nums2` надо докопировать. Начинай с самого честного условия, а сужай, только если видишь, что работа фактически кончается раньше.

## Свойства решения

| Характеристика | Значение |
|---|---|
| Время | `O(nums1Count + nums2Count)` — один проход; лучший и худший случай совпадают по порядку |
| Память | `O(1)` — три индекса, дополнительного массива нет |
| Проходов по входу | один, справа налево |
| Ранний выход | есть, но не в виде `return`: цикл останавливается, как только исчерпан `nums2` — остаток `nums1` уже стоит на своих местах и копировать его не нужно |
| Изменяет ли вход | да, `nums1` перезаписывается — это требование условия; `nums2` только читается |
| Требования к входу | оба массива обязаны быть отсортированы, а в хвосте `nums1` должно быть ровно `nums2Count` свободных мест |
| Устойчивость (stability) | сохраняется, и это следствие строгого `>` в сравнении: при равных элементах в хвост уходит элемент из `nums2`, значит элемент из `nums1` остаётся левее него |
| Работа на потоке | частично: слияние по природе потоковое, но конкретно эта запись требует произвольного доступа к концу `nums1` |
| Детерминированность | да |
| Завершаемость | `writeIndex` уменьшается на каждой записи и ограничен нулём снизу |
| Вырожденные входы | `nums2` пуст — цикл не начинается, `nums1` уже готов; `nums1Count == 0` — весь `nums2` копируется в хвост |

Альтернатива для сравнения: слить в новый массив и скопировать обратно. Время то же, но память становится `O(n)`, а условие требует именно работы на месте.
