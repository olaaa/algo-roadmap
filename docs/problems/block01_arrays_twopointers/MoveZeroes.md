# 283. Move Zeroes
*Перемещение нулей (дословно: перемести нули)*

**Сложность:** Easy · **Паттерн:** два указателя (чтение и запись) · **Класс:** `block01_arrays_twopointers.MoveZeroes`

## Условие

Дан целочисленный массив `nums`. Нужно перенести все нули в конец массива, сохранив **относительный порядок** остальных элементов.

> **Относительный порядок сохранён** — значит ненулевые элементы идут друг за другом в том же порядке, в каком они стояли в исходном массиве. Для входа `[0, 7, 0, 0, 3, 1]` ответ `[7, 3, 1, 0, 0, 0]`, а не `[1, 3, 7, 0, 0, 0]` — хотя во втором варианте нули тоже в конце.

Изменять массив нужно **на месте** (in-place): нельзя завести второй массив и собрать ответ в нём.

## Примеры

### Пример 1

```
Вход:  nums = [0, 1, 0, 3, 12]
Выход: [1, 3, 12, 0, 0]
```

Ненулевые `1, 3, 12` сдвинулись влево в исходном порядке, два нуля ушли в конец.

### Пример 2

```
Вход:  nums = [0]
Выход: [0]
```

Двигать нечего.

### Пример 3

```
Вход:  nums = [1, 2, 3]
Выход: [1, 2, 3]
```

Нулей нет — массив остаётся без изменений.

## Ограничения

- `1 <= nums.length <= 10^4`
- `-2^31 <= nums[i] <= 2^31 - 1`
- Требуется решение in-place, без копии массива; желательно минимизировать число операций записи.

## Идея решения

Наивно — идти по массиву и при встрече нуля сдвигать весь хвост влево на одну позицию. Это `O(n²)`: на каждый ноль отдельный проход по остатку массива.

Вместо этого держим два индекса, оба идут слева направо:

- `readIndex` — просматривает **все** элементы подряд, сдвигается на каждом шаге;
- `writeIndex` — позиция, куда ляжет следующий ненулевой элемент, сдвигается **только** после записи.

Первый проход: если `nums[readIndex] != 0`, копируем значение в `nums[writeIndex]` и сдвигаем `writeIndex`. Если ноль — просто пропускаем, и между указателями копится «долг» ровно из числа пропущенных нулей.

Второй проход: после первого цикла `writeIndex` указывает на первую позицию за последним ненулевым элементом. Всё, что правее (включая её) — это места, освободившиеся от пропущенных нулей; забиваем их нулями до конца массива.

Ключевой инвариант: **в момент записи** `writeIndex <= readIndex`. Поэтому запись в `nums[writeIndex]` не может затереть ещё не прочитанное значение — читающий указатель либо впереди, либо на той же позиции (тогда элемент копируется сам в себя).

Оговорка «в момент записи» существенна: сразу после `writeIndex++` пишущий индекс на мгновение равен `readIndex + 1`, но тут же итерация заканчивается и `readIndex` тоже увеличивается. Устойчивая формулировка через счётчики: записано всегда не больше, чем просмотрено, а разница — это ровно количество пропущенных нулей.

### Вариант в один проход (через обмен)

Вместо копирования с досыпкой нулей можно на каждом ненулевом элементе делать `swap(nums[writeIndex], nums[readIndex])`. Тогда нули «всплывают» вправо сами и второй цикл не нужен. Ответ тот же, сложность та же; чуть больше операций записи, зато один цикл. На собеседовании можно назвать оба варианта — это хороший знак, что видишь развилку.

### Отличие от `MergeSortedArray`

Обе задачи из подвида «однонаправленное движение», но формы разные. Здесь **одна** коллекция и роли «читает / пишет»; в `MergeSortedArray` — **две** коллекции, по указателю чтения на каждую, плюс отдельный указатель записи. Подробнее — в `Pattern_TwoPointers.md`.

## Сложность

- **Время:** `O(n)` — каждый элемент посещается не больше двух раз.
- **Память:** `O(1)` — работаем на месте, без дополнительного массива.
