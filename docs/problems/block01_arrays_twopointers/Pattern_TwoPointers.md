# Паттерн «два указателя» (two pointers)

**Блок:** `block01_arrays_twopointers` · **Тип:** обзор паттерна (не отдельная задача)

Обзорная заметка по паттерну для всего блока. Разбор конкретных задач — в соседних файлах (`TwoSumSorted.md`, `ReverseArray.md`, `ValidPalindrome.md`, `MergeSortedArray.md`, `MoveZeroes.md`).

## В чём суть

Вместо вложенного цикла ты держишь два индекса, которые бегают по структуре и **согласованно двигаются** — навстречу друг другу или в одну сторону. За счёт этого задача решается за один проход `O(n)` вместо `O(n²)`.

Ключевая идея: ты поддерживаешь две позиции (или два конца «окна») и на каждом шаге **осознанно решаешь, какой указатель сдвинуть**, отбрасывая при этом целый пласт заведомо ненужных вариантов. Именно это отбрасывание и даёт выигрыш — ты не перебираешь все пары элементов, а на каждом шаге исключаешь целую группу из них.

## Два подвида

**Встречное движение (converging).** Указатели на концах: `leftIndex` и `rightIndex` идут навстречу. Классика — поиск пары элементов с заданной суммой в отсортированном массиве: сумма больше нужной → двигаем `rightIndex` влево (уменьшаем), меньше → `leftIndex` вправо (увеличиваем). Сюда же палиндром, «сравни с концов», container with most water.

**Однонаправленное движение (same direction).** Указатели идут в одну сторону — оба слева направо либо оба справа налево, — но с разной ролью или скоростью. Навстречу друг другу они не движутся и не «встречаются в середине»: условие остановки формулируется не через их столкновение, а через исчерпание источника данных.

Подвид неоднородный, внутри него три разные формы. Их полезно различать, потому что на собеседовании по сигналу задачи ты выбираешь именно форму, а не подвид целиком.

### Форма 1: чтение и запись по одному массиву

Один массив, два индекса: `readIndex` просматривает все элементы подряд, `writeIndex` отмечает, куда положить следующий подходящий. `readIndex` двигается на каждом шаге, `writeIndex` — только когда элемент прошёл фильтр. За счёт того что `writeIndex` никогда не обгоняет `readIndex`, запись не затирает непрочитанное.

Классика: перенос нулей в конец (`MoveZeroes`), удаление дубликатов из отсортированного массива, удаление всех вхождений заданного значения. Общая формулировка — «отфильтруй массив на месте, без дополнительной памяти».

### Форма 2: слияние двух последовательностей

Два разных источника, у каждого свой указатель чтения, плюс отдельный указатель записи. На каждом шаге сравниваются головы (или хвосты) источников, и в результат уходит подходящий элемент — тот, чей указатель после этого и сдвигается.

Классика: `MergeSortedArray`, шаг merge в сортировке слиянием, пересечение и объединение двух отсортированных списков. Здесь «два указателя» означают не два конца одной коллекции, а по указателю на коллекцию.

### Форма 3: быстрый и медленный указатель (fast/slow)

Одна последовательность, оба указателя читают, но с разной скоростью: `fast` делает два шага за шаг `slow`. Роли «запись» нет вообще — работает разница пройденного пути.

Классика (связный список): поиск цикла (алгоритм Флойда — если цикл есть, быстрый догонит медленного), поиск середины (когда быстрый дошёл до конца, медленный стоит ровно посередине), n-й элемент с конца (запустить быстрый на n шагов раньше).

### Сводка форм

| Форма | Сколько коллекций | Роли указателей | Опорный класс |
|---|---|---|---|
| Чтение/запись | одна | читает / пишет | `MoveZeroes` |
| Слияние | две | читает / читает / пишет | `MergeSortedArray` |
| Fast/slow | одна | читает быстро / читает медленно | *класса пока нет* |

## Почему он работает в разных задачах

Он работает не потому, что задачи внешне похожи, а потому, что в них есть одно общее свойство: **монотонность или упорядоченность, позволяющая по одному сравнению отсечь целую группу кандидатов.**

Пример на отсортированном массиве. Если `nums[leftIndex] + nums[rightIndex]` уже больше `target`, то `nums[rightIndex]` в паре с *любым* элементом правее `leftIndex` тоже даст перебор — значит `rightIndex` можно смело двигать влево, не проверяя эти пары элементов вручную. Одно сравнение убивает целый столбец матрицы пар. Вот откуда `O(n)` вместо `O(n²)`.

## Как распознать, что нужен именно он

Сигналы, по которым на собеседовании стоит подумать про два указателя (в скобках — опорный класс из этого блока):

1. Массив или строка отсортированы (или их можно отсортировать), и ищешь пару элементов / тройку элементов с условием на сумму или разницу. → `TwoSumSorted`
2. Задача про пару элементов, и наивное решение — двойной вложенный цикл `O(n²)`, который просят ускорить. → `TwoSumSorted`
3. Нужно модифицировать массив на месте (in-place): удалить, сдвинуть, отфильтровать без доп. памяти — тут указатель чтения и указатель записи. → `MoveZeroes` (форма 1), `ReverseArray` (обмен элементов встречными указателями)
4. Два отсортированных источника нужно объединить в один — у каждого источника свой указатель. → `MergeSortedArray` (форма 2)
5. Палиндром, симметрия, «сравни с концов». → `ValidPalindrome`
6. Связный список: найти цикл, середину, n-й элемент с конца — быстрый/медленный указатель. → *класса пока нет (списков в блоке нет — отдельная тема)*
7. Подстрока или подмассив с условием («не более K», «сумма ≤») — это уже родственный паттерн скользящее окно (sliding window), частный случай двух указателей в одну сторону. → *класса пока нет (окно ещё не реализовано)*

Быстрая эвристика для интервью: *вижу вложенный цикл по парам элементов + есть сортировка или её можно сделать → пробую два указателя.*

## Частая путаница

«Пара элементов» здесь — это два элемента из **одной** коллекции (массива). Не путать с задачами, где две **разные** коллекции (два массива): там указатели тоже бывают, но логика другая — например, слияние двух отсортированных массивов (`MergeSortedArray`), где каждый указатель бежит по своему массиву.

Второе место, где легко ошибиться, — считать любое однонаправленное движение парой «быстрый/медленный». В `MoveZeroes` и `MergeSortedArray` скорости указателей одинаковые (шаг за шаг), различаются роли: кто читает, а кто пишет. Настоящий fast/slow — это разные скорости при одинаковой роли, и он живёт в задачах на связные списки, которых в блоке нет.
