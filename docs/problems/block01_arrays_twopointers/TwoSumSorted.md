# 167. Two Sum II — Input Array Is Sorted
*Сумма двух чисел II — входной массив отсортирован*

**Сложность:** Medium · **Паттерн:** два указателя · **Класс:** `block01_arrays_twopointers.TwoSumSorted`

## Условие

Дан массив целых чисел `nums`, отсортированный по **неубыванию** (нумерация **1-based** — первый элемент имеет индекс 1, а не 0). Нужно найти два числа, дающих в сумме заданное значение `target`.

Вернуть индексы этих двух чисел — `[index1, index2]` — где `1 <= index1 < index2 <= nums.length`, оба индекса 1-based.

Гарантируется, что **ровно одно** решение существует. Одно и то же число (одну и ту же позицию) нельзя использовать дважды. Решение обязано использовать только `O(1)` дополнительной памяти.

## Примеры

### Пример 1

```
Вход:  nums = [2, 7, 11, 15], target = 9
Выход: [1, 2]
```

`2 + 7 = 9`, значит `index1 = 1`, `index2 = 2`.

### Пример 2

```
Вход:  nums = [2, 3, 4], target = 6
Выход: [1, 3]
```

`2 + 4 = 6`, значит `index1 = 1`, `index2 = 3`.

### Пример 3

```
Вход:  nums = [-1, 0], target = -1
Выход: [1, 2]
```

`-1 + 0 = -1`, значит `index1 = 1`, `index2 = 2`.

## Ограничения

- `2 <= nums.length <= 3 * 10^4`
- `-1000 <= nums[i] <= 1000`
- `nums` отсортирован по неубыванию
- `-1000 <= target <= 1000`
- существует ровно одно решение

## Почему такие ограничения

Сами по себе числа `3 * 10^4` и `1000` — это выбор авторов задачи, а не следствие
какой-то теоремы; логической необходимости именно в этих значениях нет. Но что эти
ограничения практически гарантируют — понятно, и это уже не домысел.

Длина `≤ 3 * 10^4` — сознательно небольшой предел, и смысл его в том, какие алгоритмы
он пропускает, а какие отсекает. Наивный перебор всех пар — это O(n²): при n = 3·10⁴
получается n² ≈ 9·10⁸ операций, а это уже на грани или за гранью типового лимита
времени (~1 секунда), то есть тупой двойной цикл рискует не уложиться. Задуманное же
решение двумя указателями по отсортированному массиву — это O(n): при том же n оно
отрабатывает мгновенно, с огромным запасом. Иными словами, предел подобран так, чтобы
линейное решение было тривиально быстрым, а квадратичное начинало буксовать.

Диапазон значений `-1000 ≤ nums[i] ≤ 1000` (и такой же у `target`) даёт другую гарантию:
максимальная сумма двух элементов равна `1000 + 1000 = 2000`, минимальная — `-2000`.
Всё это спокойно помещается в обычный int (граница int примерно `2,15 · 10⁹`), поэтому
переполнения при сложении `nums[leftIndex] + nums[rightIndex]` быть не может в принципе,
и о типе long думать не нужно. Плюс диапазон target совпадает с диапазоном возможных
сумм — условие согласовано само с собой.

## Идея решения

Массив отсортирован — этим и пользуемся. Ставим указатель слева (`leftIndex`) и справа (`rightIndex`) и смотрим на сумму пары:

- `sum == target` → нашли ответ, возвращаем `[leftIndex + 1, rightIndex + 1]`;
- `sum` слишком мала → двигаем `leftIndex` вправо (берём число побольше);
- `sum` слишком велика → двигаем `rightIndex` влево (берём число поменьше).

Так за один проход, без вложенных циклов и без хеш-таблицы.

## Свойства решения

| Характеристика | Значение |
|---|---|
| Время, худший случай | `O(n)` — указатели идут навстречу и встречаются в середине |
| Время, лучший случай | `O(1)` — если искомая пара стоит на самых краях, ответ найден на первой итерации |
| Память | `O(1)` — два индекса; это не выбор, а требование условия |
| Проходов по входу | один, встречное движение |
| Ранний выход | есть: `return` внутри цикла срабатывает сразу, как только сумма совпала с `target` |
| Изменяет ли вход | нет, массив только читается |
| Требования к входу | вход обязан быть отсортирован — на неотсортированном алгоритм молча вернёт неверный ответ |
| Работа на потоке | невозможна: нужен произвольный доступ к обоим концам массива |
| Детерминированность | да, случайности нет |
| Завершаемость | `leftIndex` только растёт, `rightIndex` только убывает, цикл идёт до их пересечения |
| Поведение вне гарантий условия | по условию решение существует всегда; если пары нет, метод доходит до конца цикла и возвращает `{-1, -1}` |

Наивное решение для сравнения — двойной цикл по всем парам, `O(n²)`, и отсортированность в нём не используется вовсе.
