# 20. Valid Parentheses

parentheses [pəˈrenθəsiːz] — множественное число; единственное parenthesis [pəˈrenθəsɪs]

*Корректная скобочная последовательность*

**Сложность:** Easy · **Паттерн:** стек · **Класс:** `block02_strings_stack.ValidParentheses`

## Условие

Дана строка `s`, состоящая только из символов `(`, `)`, `[`, `]`, `{`, `}`. Нужно определить, является ли она корректной
скобочной последовательностью.

Строка корректна, если выполняются три условия:

1. каждая открывающая скобка закрыта скобкой **того же типа**;
2. скобки закрыты в **правильном порядке** — то есть скобка, открытая позже, закрывается раньше;
3. каждой закрывающей скобке соответствует ранее открытая скобка.

Пустая строка считается корректной.

## Примеры

### Пример 1

```
Вход:  s = "()"
Выход: true
```

### Пример 2

```
Вход:  s = "()[]{}"
Выход: true
```

Три независимые пары подряд — каждая открывается и тут же закрывается.

### Пример 3

```
Вход:  s = "(]"
Выход: false
```

Тип не совпал: открыли круглую, закрываем квадратной.

### Пример 4

```
Вход:  s = "([)]"
Выход: false
```

Обе пары на месте — круглая и квадратная, — но нарушен порядок закрытия. Квадратная открыта **позже** круглой, значит
закрыться обязана **раньше** неё. Здесь же первой идёт `)`, то есть круглую пытаются закрыть, пока квадратная ещё
открыта.

```
( [ ) ]
│ │ │ │
│ └─┼─┘   квадратная: открыта 2-й, закрыта 4-й
└───┘     круглая:    открыта 1-й, закрыта 3-й
```

Дуги пересекаются, а должны быть вложены одна в другую. Корректный вариант тех же скобок — `"([])"`.

### Пример 5

```
Вход:  s = "("
Выход: false
```

Скобка открыта и не закрыта. Строка кончилась, а работа — нет.

## Ограничения

- `1 <= s.length <= 10^4`
- `s` состоит только из символов `()[]{}`

## Почему такие ограничения

Алфавит из шести символов — важное упрощение: не нужно ничего пропускать или игнорировать, каждый символ строки заведомо
является скобкой и делится ровно на две категории — открывающая или закрывающая. Поэтому в коде хватает `if` на
открывающую и `else` на всё остальное; третьей ветки «прочий символ» не требуется.

Длина до `10^4` никакой роли не играет — решение линейное и с колоссальным запасом укладывается в лимит.

## Идея решения

Ключевое наблюдение: закрывающая скобка всегда обязана закрыть **самую последнюю** из ещё не закрытых открытых скобок.
«Самая последняя из добавленных» — это в точности поведение стека (LIFO), поэтому стек и есть подходящая структура
данных.

Алгоритм одним проходом слева направо:

- встретили открывающую скобку — кладём её в стек, она ждёт своей пары;
- встретили закрывающую — снимаем со стека верхнюю открытую и проверяем, что типы совпадают.

При этом закрывающая скобка даёт сразу два повода вернуть `false`:

1. **стек пуст** — закрывать нечего, закрывающих скобок больше, чем открывающих (`")"`, `"()) "`);
2. **тип не совпал** — сняли `(`, а закрываем `]` (`"(]"`, `"([)]"`).

Обрати внимание, что случай `"([)]"` ловится именно второй проверкой: к моменту `)` на вершине стека лежит `[`, потому
что она добавлена позже.

### Что вернуть после цикла

Это самое интересное место задачи. Прошли всю строку, ни разу не нарушив правила — но `return true` здесь был бы
ошибкой. Строка `"("` не даёт ни одного нарушения внутри цикла: закрывающих скобок в ней просто нет. Однако в стеке
осталась неотработанная открытая скобка.

Поэтому финальный ответ — не `true`, а `openBrackets.isEmpty()`: работа считается сделанной, только если стек пуст, то
есть каждая открытая скобка нашла свою пару. Это общий приём для алгоритмов, которые копят состояние (см. приём 4 в [
`heuristics.md`](../../heuristics.md)).

### Второй вариант: класть в стек ожидаемую закрывающую

Популярный на собеседованиях приём — вместо открывающей скобки класть в стек **ту скобку, которую мы ожидаем увидеть**.
Встретили `(` — кладём `)`. Тогда при встрече закрывающей скобки не нужна функция сопоставления типов: достаточно
сравнить символ с вершиной стека напрямую.

Логика идентична, но кода меньше и сравнение одно. Обе реализации есть в классе — полезно уметь показать любую и
объяснить, почему они эквивалентны.

## Свойства решения

Обе реализации (стек открывающих и стек ожидаемых закрывающих) по свойствам неразличимы, разница только в том, что кладётся в стек.

| Характеристика | Значение |
|---|---|
| Время, худший случай | `O(n)` — правильная скобочная последовательность просматривается целиком |
| Время, лучший случай | `O(1)` — первый же символ закрывающий, стек пуст, ответ `false` немедленно |
| Память, худший случай | `O(n)` — строка `"((((("`: вся уходит в стек |
| Память, лучший случай | `O(1)` — строка вида `"()()()"`: в стеке никогда не больше одной скобки |
| Проходов по входу | один |
| Ранний выход | есть, два: пустой стек при закрывающей скобке и несовпадение типа — оба дают `return false` не досматривая строку |
| Изменяет ли вход | нет, строка только читается |
| Требования к входу | по условию только скобочные символы; на любых других символах поведение условием не определено |
| Работа на потоке | да по природе алгоритма: решение о символе принимается сразу, заглядывать вперёд не нужно. Потоковой версии в классе нет |
| Детерминированность | да |
| Завершаемость | индекс растёт на каждой итерации до длины строки |
| Ответ после цикла | не `true`, а `stack.isEmpty()`: незакрытые скобки видны только по остатку — [приём 4 из шпаргалки](../../heuristics.md) |

Решения за `O(1)` памяти у общей задачи нет. Оно появляется только в вырожденном варианте с **одним** типом скобок —
тогда стек вырождается в счётчик: `+1` на открывающую, `-1` на закрывающую, ответ — счётчик ни разу не ушёл в минус и в
конце равен нулю. Хороший дополнительный вопрос от интервьюера; здесь он не применим, потому что типов три и счётчик не
помнит порядок.

## Про эту задачу на собеседовании

По сверке с книгой Макдауэлл ([`plan-vs-mcdowell-crosscheck.md`](../../../plan-vs-mcdowell-crosscheck.md)) прямого
аналога этой задачи в книге **нет** — там есть только задача 8.9 «Скобки» про генерацию всех валидных комбинаций, что
совсем другое. При этом проверка корректности скобок — одна из самых частых задач на секции в Т-Банке. То есть готовить
её нужно именно по этому файлу, книга не подстрахует.
