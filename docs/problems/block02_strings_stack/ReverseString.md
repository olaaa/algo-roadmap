# 344. Reverse String

*Разворот строки (дословно: развернуть строку)*

**Сложность:** Easy · **Паттерн:** два указателя, встречное движение · **Класс:** `block02_strings_stack.ReverseString`

## Условие

Дан массив символов `s`. Развернуть его — поставить символы в обратном порядке.

Модифицировать нужно **на месте (in-place)**, без выделения второго массива, с `O(1)` дополнительной памяти. Метод ничего не возвращает: результат — изменённый входной массив.

Обрати внимание, что на вход подаётся именно `char[]`, а не `String`. Так сделано намеренно: `String` в Java неизменяем, и «развернуть его на месте» невозможно в принципе.

## Примеры

### Пример 1

```
Вход:  ['h','e','l','l','o']
Выход: ['o','l','l','e','h']
```

### Пример 2

```
Вход:  ['H','a','n','n','a','h']
Выход: ['h','a','n','n','a','H']
```

Чётная длина: центральной позиции нет, все символы участвуют в обменах.

### Пример 3

```
Вход:  ['a']
Выход: ['a']
```

Один символ — менять не с чем, цикл не начинается.

## Ограничения

- `1 <= s.length <= 10^5`
- `s[i]` — печатаемый символ ASCII
- решение обязано работать на месте, `O(1)` дополнительной памяти

## Почему такие ограничения

Требование `O(1)` памяти — это и есть вся задача. Без него решение тривиально: создать новый массив и заполнить его с конца. Именно запрет на второй массив заставляет применить два указателя с обменом.

Оговорка «печатаемый ASCII» снимает вопрос про суррогатные пары: все символы влезают в один `char`, и посимвольный разворот ничего не ломает.

## Идея решения

Ставим два указателя на концы: `leftIndex` в начало, `rightIndex` в конец. Меняем элементы местами и сдвигаем указатели навстречу друг другу. Когда они встретились — работа окончена.

```java
int leftIndex = 0;
int rightIndex = s.length - 1;
while (leftIndex < rightIndex) {
    char temp = s[leftIndex];
    s[leftIndex] = s[rightIndex];
    s[rightIndex] = temp;
    leftIndex++;
    rightIndex--;
}
```

Это встречное движение — первый подвид приёма «два указателя», разобранного в [`Pattern_TwoPointers.md`](../block01_arrays_twopointers/Pattern_TwoPointers.md).

### Почему условие именно `leftIndex < rightIndex`

Строгое неравенство, а не `<=`. Разница видна на нечётной длине: указатели сходятся в одной точке, и `leftIndex == rightIndex` означает, что оба смотрят на центральный символ. Менять его сам с собой бессмысленно — три операции ради ничего.

На чётной длине указатели никогда не совпадают: они перескакивают друг через друга, и `leftIndex < rightIndex` перестаёт выполняться сразу после последнего обмена.

Каждый обмен ставит на места **сразу два** символа, поэтому итераций ровно `n/2`, а не `n`.

### Про временную переменную

Обмен требует третьей ячейки: без неё первое присваивание затрёт значение, которое ещё понадобится. Это не то же самое, что в [`MoveZeroes`](../block01_arrays_twopointers/MoveZeroes.md), где нули — константа и промежуточная переменная не нужна.

## Свойства решения

| Характеристика | Значение |
|---|---|
| Время | `O(n)` — ровно `n/2` итераций, в каждой три присваивания; лучший и худший случай совпадают |
| Память | `O(1)` — два индекса и одна временная переменная, копии массива нет |
| Проходов по входу | один, встречное движение |
| Ранний выход | нет и быть не может: каждая пара обязана поменяться местами |
| Изменяет ли вход | да, массив разворачивается на месте — это требование условия, метод ничего не возвращает |
| Требования к входу | никаких; на вход подаётся `char[]`, а не `String`, потому что `String` в Java неизменяема |
| Работа на потоке | невозможна: нужен доступ к обоим концам сразу |
| Детерминированность | да |
| Завершаемость | указатели движутся навстречу, цикл идёт до их встречи |
| Вырожденные входы | пустой массив и массив из одного символа: цикл не начинается, ответ уже верен |
