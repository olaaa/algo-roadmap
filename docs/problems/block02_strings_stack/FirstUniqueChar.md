# 387. First Unique Character in a String

*Первый уникальный символ в строке*

**Сложность:** Easy · **Паттерн:** счётчик частот, два прохода · **Классы:** `block02_strings_stack.FirstUniqueChar`, `block02_strings_stack.FirstUniqueCharLinkedHashMap`

## Условие

Дана строка `s`. Найти **первый неповторяющийся** символ и вернуть его индекс. Если такого символа нет — вернуть `-1`.

Неповторяющийся значит «встречается в строке ровно один раз». Первый — по позиции в строке, а не по алфавиту.

## Примеры

### Пример 1

```
Вход:  s = "leetcode"
Выход: 0
```

Символ `l` встречается один раз и стоит на позиции 0.

### Пример 2

```
Вход:  s = "loveleetcode"
Выход: 2
```

Тонкий случай: `l` тоже встречается, но уже дважды (позиции 0 и 4), поэтому не подходит. Первый уникальный — `v` на позиции 2.

Уникальных здесь четыре: `v` (2), `t` (7), `c` (8), `d` (10). Если искать ответ, перебирая **массив счётчиков**, то первым со счётчиком 1 окажется `c` — потому что в массиве буквы лежат в алфавитном порядке. Ответ был бы 8 вместо 2. Идти надо по строке.

### Пример 3

```
Вход:  s = "aabb"
Выход: -1
```

Уникальных символов нет вовсе — срабатывает фолбэк после цикла.

### Пример 4

```
Вход:  s = "z"
Выход: 0
```

Один символ — он же и уникальный.

## Ограничения

- `1 <= s.length <= 10^5`
- `s` состоит только из строчных латинских букв

## Почему такие ограничения

Алфавит из 26 строчных букв — то же упрощение, что и в [`ValidAnagram`](ValidAnagram.md): вместо хеш-таблицы хватает массива `int[26]` с индексом `symbol - 'a'`. Память не зависит от длины строки, поэтому по памяти решение `O(1)`. Подробный разбор формулы — в [`ValidAnagram.md`](ValidAnagram.md), раздел «Почему работает `symbol - 'a'`».

Длина до `10^5` отсекает решение в лоб: «для каждого символа пройти всю строку и посчитать, сколько раз он встречается» — это `O(n²)`, на сотне тысяч символов уже неприемлемо.

## Идея решения

Ключевое наблюдение: чтобы понять, уникален ли первый символ, надо знать про всю строку целиком. Значит одним проходом не обойтись — сначала собираем полную картину, потом ищем ответ.

**Первый проход считает частоты.** Идём по строке и увеличиваем счётчик соответствующей буквы.

**Второй проход ищет ответ — и идёт по строке, а не по массиву счётчиков.** Это принципиально. В массиве счётчики лежат в алфавитном порядке, а нам нужен первый по позиции в строке. Как только встретили символ со счётчиком 1 — возвращаем его индекс.

Если второй цикл дошёл до конца и ничего не нашёл — уникальных символов нет, возвращаем `-1`.

```java
int[] letterCounts = new int[26];
for (int currentIndex = 0; currentIndex < s.length(); currentIndex++) {
    letterCounts[s.charAt(currentIndex) - 'a']++;
}
for (int currentIndex = 0; currentIndex < s.length(); currentIndex++) {
    if (letterCounts[s.charAt(currentIndex) - 'a'] == 1) {
        return currentIndex;
    }
}
return -1;
```

### Что делает каждая переменная

| Переменная | Что хранит | Зачем она нужна |
|---|---|---|
| `s` | вход, строка | читается ДВАЖДЫ: первым проходом ради частот, вторым ради порядка. Второе чтение и есть причина, по которой строку нельзя забыть после подсчёта |
| `LOWERCASE_LETTER_COUNT` | константу 26 | размер алфавита из условия; в коде вместо голого числа стоит имя |
| `NOT_FOUND` | константу −1 | значение, которого требует LeetCode, когда уникального символа нет. Имя объясняет, что это не индекс, а признак «не найдено» |
| `letterCounts` | 26 счётчиков, по одному на букву | сводка по всей строке. Массив, а не карта: алфавит известен заранее, и адресация `символ - 'a'` дешевле хеширования |
| `currentIndex` | позицию в строке | заводится дважды, в каждом цикле своя переменная; в первом цикле это позиция подсчитываемого символа, во втором — кандидат в ответ, он же и возвращается |

Обрати внимание, чего в решении НЕТ: ни переменной «лучший кандидат», ни флага «нашли». Они не нужны, потому что ответ возвращается сразу из цикла, а не копится — [приём 3 из шпаргалки](../../heuristics.md).

В варианте с `LinkedHashMap` набор другой: карта `symbolStats` заменяет и массив счётчиков, и строку во втором проходе, а значением в ней лежит `record CountAndFirstIndex(int count, int firstIndex)` — счётчик вместе с позицией первого появления. Позицию приходится хранить явно именно потому, что второй проход идёт уже не по строке, и взять индекс больше неоткуда. Ключ там `Integer` — кодовая точка, а не `char`, иначе эмодзи развалилось бы на две половины суррогатной пары.

### Почему два прохода, а не один

Соблазн — обойтись одним циклом. Не выйдет: решение про символ на позиции `i` зависит от того, что стоит **правее** него, а на момент первого прохода правая часть строки ещё не просмотрена. Такой вид задач требует, чтобы вся информация была собрана до начала поиска.

Два прохода не портят сложность: `O(n) + O(n) = O(n)`.

Это приём 6 из [`heuristics.md`](../../heuristics.md) — там же разобрано, почему второй цикл обязан идти по строке, а не по сводке.

### Куда ставить `return`

Утверждение здесь — «**существует** символ со счётчиком 1». Значит находка внутри цикла (`return currentIndex`), а «не найдено» — после цикла (`return -1`). Это приём 3 из [`heuristics.md`](../../heuristics.md), и фолбэк после цикла — та самая ветка, на которую чаще всего забывают тест.

### Альтернатива: `LinkedHashMap`

Отдельный класс `FirstUniqueCharLinkedHashMap`.

Если бы алфавит был произвольным, естественной заменой массиву стала бы `LinkedHashMap` — она обходится в порядке вставки ключей, то есть в порядке первого появления символа в строке. Поэтому второй проход идёт по самой карте, а строка больше не нужна.

Но за это приходится платить: раз строку мы во втором проходе не читаем, индекс взять неоткуда, и его надо хранить в значении вместе со счётчиком. В реализации это `record CountAndFirstIndex(int count, int firstIndex)`.

Стоит назвать этот вариант на собеседовании как обобщение, но для условий задачи он хуже: `O(k)` памяти вместо `O(1)`, упаковка ключа, хеширование на каждом обращении.

#### Ключ карты — кодовая точка

Ключ карты — `Integer`, кодовая точка. Обход идёт через `codePointAt`, шаг цикла — `Character.charCount(codePoint)`.

Возвращаемый индекс остаётся в `char`-единицах, как требует LeetCode.

Устройство кодовых точек и суррогатных пар — в [`docs/datastructures/String.md`](../../datastructures/String.md).

## Свойства решений

| Время | `O(n)` | `O(n)` в среднем | `O(n²)` |
| Память | `O(1)` — всегда 26 ячеек | `O(k)`, где `k` — число различных символов | `O(1)` |

| Требования к входу | только строчные латинские буквы: индекс в массиве считается как `символ - 'a'` | любые символы, включая эмодзи — ключ хранится кодовой точкой | любые символы |
| Детерминированность | да | да | да |
| Устойчивость к деградации | худшего случая нет | `O(1)` у хеш-таблицы — амортизированная оценка | худшего случая нет, но и базовая оценка квадратичная |
| Фолбэк после цикла | `return -1`, когда уникальных не нашлось — самая частая непокрытая тестом ветка | то же | то же |
