# Как дерево записывают в условии задачи

Справочник по нотации, а не разбор задачи. Запись одинакова во всех задачах про деревья, поэтому она вынесена отдельно.

## Запись по уровням

Дерево задают массивом: обход **в ширину слева направо**, пропущенные потомки записаны как `null`.

```
Вход:  root = [3, 9, 20, null, null, 15, 7]

        3
       / \
      9   20
         /  \
        15   7
```

Читается это так: первый элемент — корень, дальше идут потомки узлов в том порядке, в каком сами узлы встретились.

## Как нарисовать дерево по записи

Правило одно: **числа идут парами, и каждая пара — это левый и правый потомок одного узла**. Узлы получают свою пару по порядку появления, сверху вниз и слева направо. Пустой узел (`null`) пару не получает: детей у него быть не может.

Дальше нужен только список тех, **кому ещё не выдали детей**. Разберём `[3, 9, 20, null, null, 15, 7]` по шагам.

### Начало: первое число — корень

```
        3
```

Кому ещё не выдали детей: `3`

### Шаг 1: берём тройку, выдаём ей `9` и `20`

```
        3
       / \
      9   20
```

Тройка своё получила — вычёркиваем её из списка. Появились двое новых, дописываем их в конец.

Кому ещё не выдали детей: `9, 20`

### Шаг 2: берём девятку, выдаём ей `null` и `null`

```
        3
       / \
      9   20
     / \
   нет нет
```

Девятку вычёркиваем. Новых узлов не появилось: оба потомка пустые.

Кому ещё не выдали детей: `20`

### Шаг 3: берём двадцатку, выдаём ей `15` и `7`

```
        3
       / \
      9   20
         /  \
        15   7
```

Двадцатку вычёркиваем, дописываем в конец `15` и `7`.

Кому ещё не выдали детей: `15, 7`

### Конец: массив кончился

Выдавать больше нечего, значит `15` и `7` детей не получат — они листья. Дерево готово.

### Почему шагов всего три

Не потому, что узлов три, а потому, что **закончился массив**. Узлы `15` и `7` так и остались в списке ожидающих: до них раздача не дошла.

И отсюда же ответ на вопрос, почему список на каждом шаге разный. Это не перечень всех узлов дерева, а список тех, кому ещё не выдали детей: на каждом шаге одного вычёркивают, а новых дописывают в конец.

В коде этот список — обычная очередь (`Queue`): берут с начала, дописывают в конец. Отсюда и название «обход в ширину».

### Два правила, из которых всё следует

1. у **непустого** узла всегда читаются два значения — левый и правый потомок, даже если оба `null`;
2. `null` в список ожидающих не попадает, поэтому его собственных потомков в массиве нет вовсе.

Второе правило и делает запись компактной: пустые ветки не разрастаются.

Хвостовые `null` принято опускать. Записи `[1, 2]` и `[1, 2, null]` описывают одно и то же дерево.

## Пример с пропусками внутри

`[1, null, 2, null, 3]` — тот же порядок действий.

**Начало.** Первое число — корень.

```
        1
```

Кому ещё не выдали детей: `1`

**Шаг 1.** Берём единицу, выдаём ей `null` и `2`: левого потомка нет, правый — двойка.

```
        1
       / \
     нет  2
```

Кому ещё не выдали детей: `2` — пустой потомок в список не идёт.

**Шаг 2.** Берём двойку, выдаём ей `null` и `3`.

```
        1
         \
          2
         / \
       нет  3
```

Кому ещё не выдали детей: `3`

**Конец.** Массив кончился, тройка остаётся листом:

```
        1
         \
          2
           \
            3
```

Здесь важны два места. Первое: `null` занял ровно одну ячейку — место левого потомка единицы — и на этом закончился, дальше чтение продолжилось как обычно. Второе: в список ожидающих `null` не попал, поэтому на следующем шаге брали двойку, а не его.

## Откуда известно, что потомков ровно два

Не из массива, а из **типа входа**. На вход подаётся `TreeNode`, а у него всего два поля-ссылки:

```java
public class TreeNode {
    public int val;
    public TreeNode left;
    public TreeNode right;
}
```

Третьего потомка негде хранить. Название задачи говорит о том же: **binary** tree — двоичное дерево, у узла не больше двух детей. Отсюда и «пара значений на узел» в записи: пара — потому что полей ровно два.

Из этого следует и граница применимости: запись по уровням годится **только для двоичного дерева**. Другие структуры в условиях задают иначе, и видно это по сигнатуре:

| Что за структура | Как задают в условии |
|---|---|
| двоичное дерево | массив по уровням с `null` — то, что разбирается здесь |
| дерево с любым числом детей | список детей у каждого узла, часто с `null` как разделителем групп |
| произвольный граф | список рёбер `[[0,1],[1,2]]` или список смежности |
| сетка, лабиринт, острова | двумерный массив, соседство по четырём направлениям |

## Два способа положить дерево в массив

Массивом дерево можно записать **двумя разными способами**, и оба законны. Путаница возникает потому, что на некоторых деревьях они дают одинаковый результат.

### Способ 1: полное представление, по формуле

Ячейка отводится каждой позиции дерева, включая пустые. Тогда работает арифметика:

```
потомки узла с индексом i  →  2i + 1 и 2i + 2
родитель узла с индексом i →  (i − 1) / 2
```

Так устроена двоичная куча — `PriorityQueue` в Java хранит элементы именно так.

### Способ 2: запись по уровням, очередью

Пишутся только реально существующие узлы и их прямые потомки. Потомков у `null` не бывает, поэтому и в массиве их нет. Так задают деревья в условиях задач, и разбирается такая запись очередью — как в разделах выше.

### На плотном дереве способы совпадают

Возьмём дерево из первого примера:

```
        3
       / \
      9   20
         /  \
        15   7
```

По формуле: корень `3` на индексе 0; его дети на 1 и 2 — `9` и `20`; дети девятки на 3 и 4 — оба пустые; дети двадцатки на 5 и 6 — `15` и `7`.

```
[3, 9, 20, null, null, 15, 7]
```

Это в точности запись из условия. **Совпало** — потому что пропуски здесь только на последнем уровне и никого не сдвигают. Именно из-за таких случаев кажется, будто формула работает всегда.

### На дереве с пропуском внутри — расходятся

```
        1
         \
          2
           \
            3
```

| Способ | Запись | Ячеек |
|---|---|---|
| запись по уровням | `[1, null, 2, null, 3]` | 5 |
| полное представление | `[1, null, 2, null, null, null, 3]` | 7 |

В полном представлении у `null` на индексе 1 всё равно резервируются места под детей — индексы 3 и 4, — хотя детей у него быть не может. Из-за этого тройка съезжает с индекса 4 на индекс 6.

Отсюда правило: **применять формулу к записи из условия нельзя**. В ней у пустых узлов места под детей не зарезервированы, и индексы после первого же внутреннего пропуска перестают сходиться.

### Почему в условиях выбран второй способ

Размер полного представления определяется не числом узлов, а высотой: нужно `2^(высота + 1) − 1` ячеек. Дерево из ста узлов, вытянутое в цепочку, имеет высоту сто — и потребует `2¹⁰¹` ячеек вместо ста.

| | Запись по уровням | Полное представление |
|---|---|---|
| что в массиве | реально существующие узлы и их прямые потомки | каждая позиция дерева, включая пустые |
| как восстановить | очередью | формулой `2i + 1`, `2i + 2` |
| размер зависит от | числа узлов | высоты дерева |
| цепочка из `10^4` узлов | около `2 · 10^4` ячеек | `2¹⁰⁰⁰¹ − 1` ячеек — столько памяти не существует |
| где встречается | условия задач, любая форма дерева | `PriorityQueue`, двоичная куча — там дерево заведомо плотное |

Практический вывод: увидев в условии массив с `null`, **не пересчитывать индексы, а восстанавливать дерево очередью**.

## Обратная задача: записать дерево массивом

То же самое, только наоборот. Список ожидающих ведётся так же — это узлы, чьих детей ещё не записали:

1. записать значение корня, поставить корень в список ожидающих;
2. взять первого из списка, дописать в массив **оба** его потомка — значение или `null`;
3. непустых потомков дописать в конец списка, самого узла вычеркнуть;
4. повторять, пока список не опустеет;
5. в конце отбросить хвостовые `null`.

Проверить себя можно по числу ячеек: у дерева из `n` узлов получится `n` значений плюс по одному `null` на каждую пустую ветку.

## Где это в коде проекта

`TreeNode.fromLevelOrder` в пакете `block06_trees_graphs` собирает дерево ровно по правилам выше. Она нужна только тестам: примеры из условия задаются в том же виде, в каком написаны на LeetCode, и не приходится строить дерево вручную через конструкторы.

Запись, в которой значения остались, а выдавать их некому (`[1, null, null, 5]`: после двух `null` список ожидающих пуст, а пятёрка ещё не прочитана), метод считает ошибкой и бросает `NoSuchElementException`. На LeetCode такие записи не встречаются.

`TreeNode.toLevelOrder` — обратная операция из раздела выше: дерево в запись, хвостовые `null` отброшены. Нужна тестам самого `TreeNode`: запись → дерево → запись должна вернуть исходную запись.

Рядом лежит `TreeNode.chainOfLength` — вырожденное дерево-цепочка, у которого есть только правые потомки, значения от нуля по порядку. В записи по уровням оно выглядит как `[0, null, 1, null, 2, …]`.

Тесты всех трёх методов — в `main()` класса `TreeNode`.
