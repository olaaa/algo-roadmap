## В чём суть

Обход графа — это способ систематически посетить все достижимые вершины, ни одну не пропустив и ни одну не обойдя дважды. Оба классических обхода устроены по одной схеме:

1. завести контейнер и положить туда стартовую вершину;
2. пока контейнер не пуст — достать вершину, обработать её, положить её соседей;
3. помеченные посещёнными вершины повторно не обрабатывать.

Контейнер хранит **фронт** — вершины, которые уже обнаружены, но ещё не обработаны.

## Ключевая идея: стратегию задаёт контейнер

Алгоритм сам по себе один. Всё различие между обходом в глубину и обходом в ширину — в том, **кого достать следующим**, то есть в дисциплине контейнера.

| Обход | Контейнер | Кого достаём | Что получается |
|-------|-----------|--------------|----------------|
| В глубину (depth-first search, DFS) | стек, LIFO | самое свежее | ныряем по одной ветке до упора, назад — только когда идти некуда |
| В ширину (breadth-first search, BFS) | очередь, FIFO | самое старое | обрабатываем вершины слоями по расстоянию от старта |

Стек отдаёт последнюю обнаруженную вершину — поэтому мы тут же проваливаемся в неё, потом в её соседа, и так до тупика. Отсюда «в глубину».

Очередь отдаёт самую раннюю — поэтому пока не обработаны все вершины на расстоянии 1, ни одна вершина на расстоянии 2 очереди не дождётся. Слои физически не могут перемешаться. Отсюда «в ширину».

## Код: разница в одну строку

```java
// обход в глубину: стек
void dfs(Node start) {
    Deque<Node> pending = new ArrayDeque<>();
    pending.push(start);
    while (!pending.isEmpty()) {
        Node current = pending.pop();
        if (!visited.add(current)) {
            continue;
        }
        for (Node next : current.neighbours()) {
            pending.push(next);
        }
    }
}

// обход в ширину: очередь. Отличаются только тип контейнера и имена методов
void bfs(Node start) {
    Queue<Node> pending = new ArrayDeque<>();
    pending.offer(start);
    while (!pending.isEmpty()) {
        Node current = pending.poll();
        if (!visited.add(current)) {
            continue;
        }
        for (Node next : current.neighbours()) {
            pending.offer(next);
        }
    }
}
```

## Что из этого следует на практике

**BFS находит кратчайший путь по числу рёбер, DFS — нет.** Прямое следствие послойности: вершина попадает в обработку тогда, когда до неё дошёл ближайший слой, значит найденное расстояние минимально. У DFS первый найденный путь может оказаться сколь угодно кривым. Это работает только для невзвешенного графа; при разных весах рёбер нужна приоритетная очередь.

**Память ведёт себя по-разному.** Очередь BFS хранит целый слой, то есть растёт как ширина графа. Стек DFS хранит текущую ветку, то есть растёт как глубина. На широком и мелком графе дешевле DFS, на узком и глубоком — BFS.

**Рекурсивный DFS проще, но упирается в стек вызовов.** На вырожденном дереве или длинной цепочке он падает с `StackOverflowError`; у явного стека предел — только куча.

## Рекурсивный DFS и итеративный обходят соседей в разном порядке

Разница в том, когда вершина раскрывается. Рекурсия, дойдя до первого соседа, немедленно проваливается в него и не возвращается, пока не обойдёт его целиком — про остальных соседей она в этот момент даже не вспоминает. Итеративная версия наоборот: сначала кладёт в стек всех соседей сразу, и только потом снимает одного — а снимается последний положенный.

Пусть у вершины `A` соседи `B`, `C`, `D`:

```
рекурсивно:      обходим B со всем его поддеревом → потом C → потом D

через стек:      положили B, C, D
                 ┌───┬───┬───┐
                 │ B │ C │ D │ ← вершина стека
                 └───┴───┴───┘
                 сняли D → уходим вглубь через D, B достанется последним
```

Порядок соседей переворачивается. Если нужно совпадение с рекурсией, соседей кладут в стек в обратном порядке.

Итеративная версия при этом не «неправильная»: обход в глубину не диктует, в каком порядке перебирать соседей. Оба варианта — честный DFS, просто с разным порядком.

## Почему `visited` проверяется при снятии

В контейнере одна и та же вершина может лежать в нескольких экземплярах: её успели положить несколько разных соседей до того, как до неё дошла очередь. Поэтому проверка `visited` стоит **при снятии**, а не при добавлении — иначе вершина будет обработана дважды.

Альтернатива — помечать вершину посещённой в момент добавления в контейнер. Тогда дубликатов в контейнере не будет вовсе, и для BFS это даже предпочтительнее, потому что экономит память. Важно только не смешивать две схемы в одном коде.

## Как распознать, что нужен именно он

1. Просят **кратчайший путь / минимальное число шагов** в невзвешенном графе или сетке. → BFS
2. Спрашивают, **достижима ли** вершина, есть ли путь, есть ли цикл. → любой из двух, DFS обычно короче
3. Нужно обойти **связную область**: острова на сетке, заливка краской, компоненты связности. → DFS (в том числе рекурсивный)
4. Нужен обход **по уровням**: вывести дерево по слоям, найти глубину, правый профиль дерева. → BFS
5. Требуется **топологическая сортировка**, порядок сборки с зависимостями. → DFS

Быстрая эвристика для интервью: *слышу «кратчайший» или «по уровням» — беру очередь; слышу «обойти всё», «есть ли путь», «залить область» — беру стек или рекурсию.*

## Частая путаница

**Сетка — это тоже граф.** Задачи вроде «количество островов» не выглядят графовыми, но клетка — вершина, а соседство по четырём направлениям — рёбра. Отдельный алгоритм тут не нужен.

**Дерево — частный случай графа**, причём без циклов. Поэтому в обходах дерева `visited` не нужен: вернуться в уже посещённую вершину невозможно. В произвольном графе без `visited` обход зациклится.

**BFS не даёт кратчайший путь во взвешенном графе.** Частая ошибка на собеседовании. Как только у рёбер появляются разные веса, нужна приоритетная очередь — и алгоритм превращается в Дейкстру.
