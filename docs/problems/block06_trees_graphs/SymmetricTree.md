# 101. Symmetric Tree

*Симметричное дерево*

**Сложность:** Easy · **Паттерн:** обход в глубину рекурсией, по двум узлам сразу · **Класс:** `block06_trees_graphs.SymmetricTree`

## Условие

Дан корень двоичного дерева. Проверить, является ли дерево зеркальным отражением самого себя, то есть симметричным относительно вертикальной оси через корень.

## Примеры

### Пример 1

```
Вход:  root = [1, 2, 2, 3, 4, 4, 3]

          1
        /   \
       2     2
      / \   / \
     3   4 4   3

Выход: true
```

Если сложить дерево пополам по вертикали через корень, левая половина ляжет на правую: `3` на `3`, `4` на `4`, `2` на `2`.

### Пример 2

```
Вход:  root = [1, 2, 2, null, 3, null, 3]

          1
        /   \
       2     2
        \     \
         3     3

Выход: false
```

Левое и правое поддеревья корня здесь одинаковы, но не зеркальны: у обоих тройка висит справа. В отражении тройка левого поддерева должна была бы оказаться слева.

Как читается запись `[1, 2, 2, null, 3, null, 3]` — в [`TreeNotation.md`](TreeNotation.md).

## Ограничения

- число узлов в дереве — от `1` до `1000`
- `-100 <= Node.val <= 100`

Follow-up из условия: решить и рекурсивно, и без рекурсии.

## Почему такие ограничения

Нижняя граница — один узел, не ноль. Значит `root` никогда не бывает `null`, и проверять его не надо: решение сразу обращается к `root.left` и `root.right`. Дерево из одного узла симметрично — оба поддерева корня пусты.

Верхняя граница в тысячу узлов задаёт предельную глубину рекурсии. Самое глубокое симметричное дерево — «галочка»: у корня два потомка, дальше левая ветвь растёт только влево, правая только вправо. На `999` узлах её глубина `500`, и столько же вложенных вызовов делает рекурсия. Для стека потока это немного; проверено тестом.

Диапазон значений на решение не влияет: значения только сравниваются на равенство.

## Идея решения

Симметрия дерева — свойство не одного поддерева, а **пары**: левое поддерево корня должно быть зеркальным отражением правого. Поэтому рекурсия идёт не по одному узлу, как в `maxDepth`, а по двум узлам одновременно — по одному с каждой стороны.

Два поддерева зеркальны, когда выполнены три условия: их корни равны по значению; левое поддерево первого зеркально правому поддереву второго; правое поддерево первого зеркально левому поддереву второго. Пары перекрёстные, и в этом вся задача: сравнивать надо не «левое с левым», а **внешнее с внешним и внутреннее с внутренним**.

```java
public static boolean isSymmetric(TreeNode root) {
    return isMirror(root.left, root.right);
}

private static boolean isMirror(TreeNode leftSubtree, TreeNode rightSubtree) {
    if (leftSubtree == null && rightSubtree == null) {
        return true;
    }
    if (leftSubtree == null || rightSubtree == null) {
        return false;
    }
    return leftSubtree.val == rightSubtree.val
            && isMirror(leftSubtree.left, rightSubtree.right)
            && isMirror(leftSubtree.right, rightSubtree.left);
}
```

`isSymmetric` только запускает проверку для двух поддеревьев корня. Сам корень ни с чем не сравнивается: он лежит на оси симметрии и отражается сам в себя.

`isMirror` отвечает на вопрос «зеркальны ли эти два поддерева». Два базовых случая: оба пусты — зеркальны; пусто ровно одно — нет, формы различаются. Если оба непусты, ответ складывается из трёх условий через `&&`: значения корней и два рекурсивных вызова на перекрёстные пары.

### Что делает каждая переменная

| Переменная | Что хранит | Зачем она нужна |
|---|---|---|
| `root` | корень всего дерева | единственный вход задачи; сам в сравнениях не участвует, только даёт два поддерева; имя из условия LeetCode |
| `leftSubtree` | корень поддерева с левой стороны от оси | первый из двух узлов, которые сравниваются; на верхнем уровне это `root.left`, глубже — узел из левой половины дерева |
| `rightSubtree` | корень поддерева с правой стороны от оси | второй узел пары; на верхнем уровне `root.right`, глубже — узел из правой половины, стоящий зеркально к `leftSubtree` |

Имена `leftSubtree` и `rightSubtree` названы по стороне от оси симметрии, а не по полю родителя: на втором рекурсивном вызове в `leftSubtree` попадает `leftSubtree.right`, то есть правый потомок, — но он по-прежнему из левой половины дерева.

### Почему рекурсия идёт по двум узлам

В `maxDepth` вопрос задаётся одному узлу: «какова твоя высота?» — и ответ складывается из ответов потомков. Здесь вопрос «симметрично ли дерево» одному узлу задать нельзя: симметрия — это отношение между двумя половинами. Единственное место, где симметрия сводится к одному узлу, — корень, и там она сразу разворачивается в вопрос про пару `root.left` и `root.right`.

Дальше пара порождает две пары. Внешняя: левый потомок левого узла и правый потомок правого — они стоят по краям дерева, друг напротив друга. Внутренняя: правый потомок левого узла и левый потомок правого — они стоят у оси, тоже друг напротив друга. Так рекурсия спускается по обеим половинам одновременно, всё время держа напротив друг друга те два узла, которые совпали бы при складывании дерева пополам.

### Почему `null` проверяется дважды

Первая проверка — базовый случай «зеркальны»: оба поддерева пусты, сравнивать нечего, и это не ошибка, а нормальное дно рекурсии. Вторая — базовый случай «не зеркальны»: с одной стороны узел есть, с другой нет. Форма уже не совпала, значение смотреть незачем. Обе проверки стоят до обращения к `val`, иначе на пустом поддереве было бы `NullPointerException`.

Объединить их в одну нельзя: у них разные ответы. Записать второй случай как `leftSubtree == null || rightSubtree == null` можно только после первого: когда оба `null` уже отсечены, `||` означает «ровно один пуст».

### Почему три условия соединены через `&&`

Утверждение «поддеревья зеркальны» — это «для всех пар узлов верно, что они совпадают». Одного несовпадения достаточно, чтобы ответ стал `false`, и `&&` делает ровно это: как только первое условие ложно, остальные не вычисляются, и рекурсия в оставшиеся пары не заходит. Значения различны — потомков не смотрим; внешняя пара не зеркальна — внутреннюю не проверяем. Это приём 3 из шпаргалки в рекурсивном виде: опровержение срабатывает мгновенно, подтверждение — только когда проверено всё.

Порядок трёх условий тоже не случаен: сравнение значений стоит первым, потому что оно дешёвое и отсекает несовпадение без спуска вглубь.

### Разбор по шагам

Пример 1, дерево `[1, 2, 2, 3, 4, 4, 3]`. В каждой строке — пара узлов, которые сравниваются:

```
isSymmetric(1)
└── isMirror(2, 2)                 значения равны, идём в пары
    ├── isMirror(3, 3)             внешняя пара: значения равны
    │   ├── isMirror(null, null) → true
    │   └── isMirror(null, null) → true
    │   вернул true
    └── isMirror(4, 4)             внутренняя пара: значения равны
        ├── isMirror(null, null) → true
        └── isMirror(null, null) → true
        вернул true
    вернул true
вернул true
```

Пример 2, дерево `[1, 2, 2, null, 3, null, 3]`:

```
isSymmetric(1)
└── isMirror(2, 2)                 значения равны, идём в пары
    └── isMirror(null, 3)          внешняя пара: слева пусто, справа 3
        вернул false
    вернул false — внутреннюю пару не проверяли
вернул false
```

Внешняя пара — левый потомок левой двойки (его нет) и правый потомок правой двойки (тройка). Форма не совпала, и `&&` оборвал проверку.

## Свойства решения

Что означает каждая строка — в [`docs/algorithm-properties.md`](../../algorithm-properties.md).

| Характеристика | Значение |
|---|---|
| Время | `O(n)` в худшем случае: каждый узел участвует ровно в одной паре. Лучший случай `O(1)` — потомки корня различаются по значению |
| Память | `O(h)`, где `h` — высота дерева: глубина рекурсии равна глубине самой длинной пары. У «галочки» из `n` узлов это `n / 2` |
| Проходов по входу | один, по обеим половинам одновременно |
| Ранний выход | да: первое несовпадение — значений или формы — обрывает все оставшиеся сравнения через `&&` |
| Изменяет ли вход | нет, дерево только читается |
| Требования к входу | хотя бы один узел — гарантировано условием, поэтому `root` на `null` не проверяется |
| Работа на потоке | нет: нужен доступ к потомкам по ссылкам с двух сторон одновременно |
| Детерминированность | полная |
| Завершаемость | каждый вызов спускается на уровень ниже по обеим сторонам; пустое поддерево хотя бы с одной стороны обрывает спуск |
| Поведение на вырожденных входах | один узел — `true`; «галочка» из `999` узлов, предел условия по глубине, проходит |

## Приёмы из шпаргалки

- **Приём 3** («для всех» против «существует») — «для всех пар узлов верно, что они совпадают»: опровержение через `&&` мгновенное, подтверждение только после того, как проверены все пары до самых листьев.
- **Приём 9** (каждая итерация обязана уменьшать задачу) — в рекурсивном виде: каждый вызов спускается на уровень ниже сразу по двум половинам, а пара пустых поддеревьев служит дном.
