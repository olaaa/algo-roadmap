# 35. Search Insert Position

*Поиск позиции для вставки (дословно: искать позицию вставки)*

**Сложность:** Easy · **Паттерн:** бинарный поиск, ответ по месту остановки · **Класс:** `block05_binary_search.SearchInsertPosition`

## Условие

Дан массив целых чисел `nums`, отсортированный **по возрастанию**, все значения различны, и число `target`.

Вернуть индекс, по которому `target` лежит в массиве. Если такого числа нет — вернуть индекс, **на который его следовало бы вставить**, чтобы массив остался отсортированным.

Требуется решение за `O(log n)`.

## Примеры

### Пример 1

```
Вход:  nums = [1, 3, 5, 6], target = 5
Выход: 2
```

Пятёрка есть в массиве, на позиции 2.

### Пример 2

```
Вход:  nums = [1, 3, 5, 6], target = 2
Выход: 1
```

Двойки нет. Её место — между `1` и `3`, то есть на позиции 1: после вставки массив станет `[1, 2, 3, 5, 6]`.

### Пример 3

```
Вход:  nums = [1, 3, 5, 6], target = 7
Выход: 4
```

Семёрка больше всех элементов, её место в хвосте. Ответ **равен длине массива** — такого индекса в массиве ещё нет, и это нормально: речь о позиции для вставки, а не о существующей ячейке.

### Пример 4

```
Вход:  nums = [1, 3, 5, 6], target = 0
Выход: 0
```

Ноль меньше всех, вставлять в самое начало.

## Ограничения

- `1 <= nums.length <= 10^4`
- `-10^4 <= nums[i] <= 10^4`
- Все значения в `nums` **различны**
- `nums` отсортирован по возрастанию
- `-10^4 <= target <= 10^4`

## Почему такие ограничения

Те же, что у [`BinarySearch.md`](BinarySearch.md), и следствия те же: длина до `10^4` означает индексы до 9 999, поэтому середина считается обычной полусуммой; `null` и пустой массив условием исключены, охранных проверок в решении нет.

Гарантия «все значения различны» здесь важнее, чем в 704: будь в массиве повторы, пришлось бы договариваться, перед каким из одинаковых значений вставлять.

Требование `O(log n)` отсекает очевидное решение «идти слева, пока элемент меньше target» — оно правильное, но линейное.

## Идея решения

Это тот же цикл, что и в задаче 704. Разница ровно в одной строке: **что возвращается после цикла**.

```java
int lowIndex = 0;
int highIndex = nums.length - 1;

while (lowIndex <= highIndex) {
    int middleIndex = (lowIndex + highIndex) / 2;
    int middleValue = nums[middleIndex];

    if (middleValue == target) {
        return middleIndex;
    }
    if (middleValue < target) {
        lowIndex = middleIndex + 1;
    } else {
        highIndex = middleIndex - 1;
    }
}
return lowIndex;
```

В 704 после цикла стоит `return -1` — «не найдено». Здесь `return lowIndex` — «вот куда вставлять».

### Что делает каждая переменная

| Переменная | Что хранит | Зачем она нужна |
|---|---|---|
| `nums` | вход, отсортированный массив | читается, не меняется |
| `target` | вход, искомое значение | второй операнд каждого сравнения |
| `lowIndex` | индекс левой границы участка поиска, включительно | всё, что левее, уже проверено и меньше `target`; после цикла эта же переменная становится ответом |
| `highIndex` | индекс правой границы участка поиска, включительно | всё, что правее, уже проверено и больше `target` |
| `middleIndex` | индекс середины текущего участка | единственная позиция, которую проверяет итерация |
| `middleValue` | значение `nums[middleIndex]` | участвует в двух сравнениях подряд — на равенство и на «меньше» |

### Почему после цикла возвращается именно `lowIndex`

Цикл поддерживает инвариант из двух половин:

```
всё, что левее lowIndex   — строго МЕНЬШЕ target
всё, что правее highIndex — строго БОЛЬШЕ target
```

Каждая итерация его сохраняет: если середина оказалась мала, она вместе со всей левой половиной уходит влево от новой `lowIndex`; если велика — вправо от новой `highIndex`.

Цикл заканчивается, когда границы разошлись, то есть `lowIndex = highIndex + 1`. Непроверенных элементов между ними не осталось. Значит слева от `lowIndex` стоят только меньшие, а начиная с `lowIndex` — только большие. Ровно это и означает «место для `target`».

Трассировка примера 2, `nums = [1, 3, 5, 6]`, `target = 2`:

```
индексы:   0   1   2   3
nums:      1   3   5   6

шаг 1:  lowIndex = 0, highIndex = 3, middleIndex = 1, nums[1] = 3
        3 > 2   значит  участок [0..0], highIndex = 0
шаг 2:  lowIndex = 0, highIndex = 0, middleIndex = 0, nums[0] = 1
        1 < 2   значит  участок [1..0], lowIndex = 1
        границы разошлись, ответ lowIndex = 1
```

Слева от позиции 1 стоит единица — меньше двойки. На позиции 1 стоит тройка — больше. Двойке между ними.

### Состояние массива на момент выхода

Тот же вывод удобно увидеть на случае, когда границы не сходятся в одной точке, а **перескакивают друг через друга**. Возьмём `nums = [1, 3, 5, 6]` и `target = 4`:

```
шаг 1:  lowIndex = 0, highIndex = 3, middleIndex = 1, nums[1] = 3
        3 < 4   значит  lowIndex = 2
шаг 2:  lowIndex = 2, highIndex = 3, middleIndex = 2, nums[2] = 5
        5 > 4   значит  highIndex = 1
        lowIndex = 2 больше highIndex = 1, цикл кончился
```

Что известно про каждую ячейку в этот момент:

| Индекс | Значение | Что про него известно |
|---|---|---|
| 0 | 1 | меньше `target` |
| 1 | 3 | меньше `target` — на нём стоит `highIndex` |
| 2 | 5 | больше `target` — на нём стоит `lowIndex` |
| 3 | 6 | больше `target` |

Граница между «меньше» и «больше» проходит между индексами 1 и 2, и четвёрке место на позиции 2 — там, где остановился `lowIndex`.

Обрати внимание: **у цикла два разных финала**. Либо участок сузился до одного элемента и границы совпали, либо участок был из двух элементов и границы разошлись, ни разу не совпав. Ответ `lowIndex` покрывает оба — отдельных веток для них не нужно.

### Почему ответ может равняться длине массива

Пример 3 даёт `4` на массиве из четырёх элементов, то есть индекс, которого в массиве нет.

Так и должно быть: позиций для вставки на одну больше, чем элементов. У массива из четырёх элементов их пять — перед первым, между соседями трижды и после последнего.

```
позиции вставки:  0     1     2     3     4
                    [1]   [3]   [5]   [6]
```

Проверять это отдельной веткой не нужно: если `target` больше всех, левая граница просто доедет до `nums.length`, и цикл закончится сам.

### Ловушка: `highIndex` кажется таким же подходящим

После цикла есть две границы, и соблазн вернуть `highIndex` велик — он ведь тоже указывает «куда-то рядом».

Но `highIndex = lowIndex - 1`, и указывает он на **последний элемент, который меньше** `target`. Это позиция соседа слева, а не место вставки. На примере 2 он равен `0` — позиция единицы, тогда как правильный ответ `1`.

Проверить себя можно на краю: если `target` меньше всех элементов, `highIndex` становится `-1`, а такой индекс позицией вставки быть не может. `lowIndex` в том же случае равен `0` — верный ответ.

### Отличие от задачи 704

| | 704 Binary Search | 35 Search Insert Position |
|---|---|---|
| что после цикла | `return -1` — фолбэк «не найдено» | `return lowIndex` — содержательный ответ |
| диапазон ответа | `0 .. n - 1` или `-1` | `0 .. n`, отрицательных нет |
| есть ли случай «нет ответа» | да | нет, ответ есть всегда |

Отсюда следствие для тестов: в 704 отдельно проверяется фолбэк, а здесь фолбэка нет вовсе — после цикла возвращается такой же полноправный ответ, как и находка внутри цикла.

Стандартный `Arrays.binarySearch` возвращает обе величины сразу: при неудаче его результат равен `-(точка вставки) - 1`. Разбор этой формулы — в [`BinarySearch.md`](BinarySearch.md), раздел про `-1`. В тестах класса ответы сверены с ней на двух тысячах значений.

## Свойства решения

Что означает каждая строка — в [`docs/algorithm-properties.md`](../../algorithm-properties.md).

| Характеристика | Значение |
|---|---|
| Время в худшем случае | `O(log n)` — участок делится пополам, пока не станет пустым |
| Время в лучшем случае | `O(1)` — `target` оказался ровно посередине |
| Память | `O(1)` — две границы, середина и её значение |
| Проходов по входу | ни одного полного: читается не больше `⌊log₂ n⌋ + 1` элементов |
| Ранний выход | да, находка возвращается прямо из цикла |
| Изменяет ли вход | нет, массив только читается |
| Требования к входу | отсортирован по возрастанию, значения различны — предусловие, метод его не проверяет |
| Работа на потоке | нет: нужен доступ к произвольному индексу |
| Детерминированность | полная: ни случайности, ни внешнего состояния |
| Завершаемость | каждая итерация уменьшает участок минимум на один элемент за счёт `+1` / `−1` в сдвигах |
| Диапазон ответа | `0 .. nums.length`, то есть на единицу шире, чем множество индексов |
| Поведение на вырожденных входах | массив из одного элемента даёт три возможных ответа: `0` при попадании и при вставке слева, `1` при вставке справа |

## Приёмы из шпаргалки

- **Приём 1** (как придумать условие цикла): границы включительные, поэтому условие нестрогое — разбор в [`BinarySearch.md`](BinarySearch.md).
- **Приём 9** (каждая итерация обязана уменьшать задачу): единицы в сдвигах границ, без них цикл вечный.

Приём 3 («для всех» против «существует») здесь **не применяется**, и это стоит заметить: у задачи нет исхода «не найдено», поэтому после цикла стоит не фолбэк, а обычный ответ.
