# Структуры данных

Справочники по структурам данных — в объёме, который нужен на собеседовании. В основном это типы стандартной библиотеки Java; исключение — двоичное дерево: готового типа в библиотеке нет, на собеседовании его приносят классом `TreeNode` из условия. Отдельно от `docs/problems/`: там разбираются конкретные задачи, здесь — инструменты, которыми задачи решаются.

Все утверждения про поведение проверены запуском на JDK 25 (JetBrains Runtime), детали внутреннего устройства — по исходникам из `src.zip` той же JDK. Это важно: часть общеизвестных фактов про `ArrayDeque` устарела и на актуальной JDK уже неверна.

## Содержание

| Файл | О чём |
|------|-------|
| [`Queue.md`](Queue.md) | Интерфейс `Queue`, шесть методов в двух вариантах, `PriorityQueue`, блокирующие очереди, роль в BFS |
| [`Deque.md`](Deque.md) | Интерфейс `Deque`, отличия от `Queue`, три группы методов, `ArrayDeque` изнутри, почему `Stack` не нужен |
| [`Stack.md`](Stack.md) | Стек как абстрактный тип данных, соотношение со стеком/очередью/деком, чем плох `java.util.Stack`, рекурсия ↔ явный стек, монотонный стек |
| [`BinaryTree.md`](BinaryTree.md) | Узел, корень, лист, поддерево; глубина против высоты; `TreeNode`; обход в глубину в трёх порядках и обход в ширину, с картинками; стек против очереди; память обходов |
| [`String.md`](String.md) | Неизменяемость и compact strings, `char` как кодовая единица UTF-16, суррогатные пары, `length()` против `codePointCount()`, безопасная нарезка через `offsetByCodePoints`, `equals` против `==` |

## Соглашения

- Иллюстрации — отдельные файлы `.svg` в подпапке `img/`, вставляются в markdown как `![подпись](img/имя.svg)`. Так они рендерятся и в IntelliJ, и на GitHub.
- Каждый справочник заканчивается разделом «Типичные вопросы на собеседовании» — короткие формулировки, которые можно проговорить вслух.
- Если утверждение проверялось запуском кода, в тексте приводится фактический вывод.
